# Перевірка перехоплення

Які з ваших субдоменів можна перехопити — CNAME-и, що вказують на
невитребувані хмарні ресурси (S3, GitHub Pages, Heroku, Azure,
Shopify, Tumblr, Pantheon, GCS…), звірені з курованим списком
фінгерпринтів: **NXDOMAIN на цілі** (найсильніша ознака
«висяка»), **сторінка-маркер невитребуваного** ресурсу провайдера
(один GET) і нюанс **закрито-відкрито** (Fastly, Vercel, Netlify,
WordPress.com закрили лазівку — їхні збіги звітуються як
«виставлено, але не перехопити», ніколи не пропускаються мовчки).

**Контракт пасивності:** DNS + один GET на кандидата, порівняння
з маркером — і нічого більше. Нічого не реєструється, нічого не
забирається; виходом є ознаки і документація провайдера. Різниця
між діагностикою дірки і її експлуатацією — це саме лінія, яку
цей скрипт не переходить.

---

## Перед запуском

1. Введіть **Domain** — кандидати збираються з фіду прозорості
   crt.sh (з лімітом **Max subdomains**); або вкажіть **Subdomains file** — тоді діє лише фільтр належності домену.
2. **Prepare Env** — встановлює `requests`, `dnspython`, `pyyaml`.
3. Натисніть **Run** (⌘↩).

## Поля

### Target

- **Domain (or subdomains file)** — реєструємий домен для збору з
  фіду.
- **Subdomains file (optional)** — по одному хосту на рядок;
  пропускає збір. Чужі хости фільтруються доменом.
- **Per-probe timeout (s)** — кожен DNS-запит і кожен GET.
- **Max subdomains** — ліміт кандидатів із фіду (10–5000,
  типовo 500).

---

## Результат

- **Вкладка Results** — таблиця (host · cname · service ·
  verdict) і звіт:
  - **🔴 dangling — target is NXDOMAIN** — ціль CNAME взагалі не
    резолвиться: ресурс зник; хто його відтворить — володіє вашим
    субдоменом.
  - **🔴 marker matches — likely claimable** — сторінка
    невитребуваного ресурсу відповіла на вашому субдомені.
  - **🟠 marker matches — service closed the hole** — форма
    виставлена, перехоплення нема (верифікація доменів).
  - **⚪ fingerprint target, no marker** — вказує на сервіс, але
    ресурс існує і обслуговується.
  - Список виправлень для червоних: прибрати CNAME або відтворити
    ресурс у **вашому** акаунті; запарковані делегації — це саме
    те, що знаходить цей звіт.
- **Артефакти** — `report.md`, `findings.json` (посилання на
  домен-доки провайдера по кожній знахідці).

### Дані, що старіють

Прапорці takeover відображають актуальні вимоги верифікації
провайдерів і застаріють — коли сервіс додасть верифікацію, зміна
— це правка YAML (`takeover_fingerprints.yaml`), не коду.

## Коди виходу

| Код | Значення |
|---|---|
| 0 | відпрацювало; знахідки — результат |
| 1 | фід недосяжний або кандидатів нема |
| 2 | помилкові аргументи: не домен, немає файла |

## Пов'язане

- **Subdomain Search** — пасивний інвентар; його вивід — у
  `--subdomains-file`.
- **CT Log Check** — історичні імена: сертифікат на зниклий
  субдомен часто означає зниклий CNAME.
- **Port Check / FW Audit** — сторона гігієни експозиції.
