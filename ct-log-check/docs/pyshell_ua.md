# Перевірка CT-логів

Кожен сертифікат, коли-небудь виданий для домену — логи прозорості
сертифікатів через фід crt.sh: **таймлайн** видач (по місяцях,
діаграмою), **емітенти** (ваш основний CA і всі інші, хто колись
видавав — головне у звіті), **вілдкарди**, кожне **ім'я**, яке
покривають сертифікати, з відокремленням ще чинних, прапорець
**сплеску» (свіжий темп проти середнього за рік) і — коли спрацьовує
ліміт JSON-фіду crt.sh для дуже великих доменів (найновіша видача у
фіді — місяці тому) — чесна примітка, що його називає, замість
обманливого «valid now: 0».

Плюс **порівняння CAA**: записи CAA домену (кому *дозволено*
видавати — через DNS-over-HTTPS, з підйомом по батьках так, як це
робить CA) проти CA, які тримають *живі* сертифікати — дозволено ✅
· поза списком 🔴 · не розпізнано ⚪ (курована таблиця не знає
кожного CA; вердикт ніколи не вгадується).

Історичний двійник живого сертифіката з TLS Audit. Пасивно: один
запит до фіду плюс пара DNS-over-HTTPS запитів.

---

## Перед запуском

1. Введіть **Domain** — реєструємий домен; у зоні уваги кожен
   сертифікат для нього і будь-якого субдомена (фід `%.домен`).
2. **Prepare Env** — встановлює `requests`.
3. Натисніть **Run** (⌘↩). Фід може бути повільним на великих
   доменах — дві повторні спроби з backoff вбудовані.

## Поля

### Target

- **Domain** — реєструємий домен (наприклад `example.com`, не
  `www.example.com`).
- **crt.sh timeout (s)** — 10–120, типовo 45.
- **Skip the CAA comparison** — вимкнено за замовчуванням:
  політика CAA фетчиться через DNS-over-HTTPS (домен і його
  батьки, підйом за RFC 8659) і порівнюється з живими емітентами.
  Пропустіть для проходу лише по crt.sh без DNS-запитів.

---

## Результат

- **Вкладка Results** — таблиця емітентів (топ-15 за кількістю),
  стовпчикова діаграма видач по місяцях, і звіт:
  - **Емітенти** — основний CA, потім *усі інші*: незнайомий CA —
    або історія (ротация), або питання (звірте акаунти ACME і лог
    API DNS-провайдера).
  - **Таймлайн** — перша й найновіша видача, кількість за останні
    30 днів, попередження про сплеск, примітка про ліміт crt.sh,
    коли вона доречна.
  - **Вілдкарди** — сертифікати `*.домен`.
  - **Імена** — чинне покриття; які імена ще *існують* — питання до
    DNS → **Subdomain Search** / **Fleet Check**.
  - **CAA — кому дозволено проти того, хто реально видавав** — рядок
    політики (або чесне «запису CAA нема — видавати може будь-який
    CA у світі»), потім кожен CA з живими сертифікатами: дозволено,
    поза списком (видано до політики чи прогалина в ній), або не
    розпізнано. Нюанс сказано прямо: CAA діє з моменту публікації —
    живий сертифікат може цілком легально передувати вашій власній
    політиці; розклад ротації — ваше рішення.
- **Артефакти** — `report.md`, `findings.json` (кожен запис: id
  сертифіката, ім'я, емітент, not_before, not_after; плюс політика
  CAA і вердикти).

## Коди виходу

| Код | Значення |
|---|---|
| 0 | відпрацювало; звіт і є історія |
| 1 | crt.sh недосяжний / не-JSON відповідь, або записів нема |
| 2 | помилкові аргументи: не домен |

## Пов'язане

- **TLS Audit** — живий сертифікат, якого ця історія стосується.
- **Subdomain Search** — імена, з того самого фіду crt.sh плюс
  пасивні джерела.
- **Fleet Check** — живий TLS усього портфеля в одній таблиці.
