# Перевірка DNSSEC

**Чи можна довіряти відповіді DNS?** Ланцюжок DS/DNSKEY валідується
від кореневого анкера IANA (KSK-2017, tag 20326) через кожну
батьківську зону аж до цілі — DS кожної делегації проти ключів
батька, кожен набір DNSKEY звіряється зі своїм DS, кожен підпис
криптографічно перевіряється **тут**, а не на слові резолвера.
Вердикти простими словами: 🟢 secure · ⚪ insecure (unsigned) · 🟠
signed but no DS at the parent · 🔴 bogus · ⚫ indeterminate.

---

## Перед запуском

1. Введіть **Domain** для валідації. Опційно — **IP резолвера**
   (8.8.8.8, 1.1.1.1, локальний): валідацію в будь-якому разі робить
   цей скрипт; резолвер — лише транспорт.
2. **Prepare Env** — встановлює `dnspython`.
3. Натисніть **Run** (⌘↩).

## Поля

### Target

- **Domain** — ім'я для валідації; ланцюжок проходить від кореня
  через TLD і кожну проміжну зону до нього. Ім'я, яке не є власною
  точкою делегування — `www.example.com` усередині `example.com` —
  це звичайні дані батьківської зони: воно успадковує її вердикт, а
  не оголошується непідписаним. Unicode-імена приймаються і
  перетворюються на punycode (`мон.укр` → `xn--l1acc.xn--j1amh`).
- **Resolver IP (optional)** — IPv4 або IPv6; типово системний
  резолвер (перша придатна адреса, не link-local). Вкажіть інший,
  щоб відділити «мій резолвер бреше/ламається» від «зона зламана».
- **Per-query timeout (s)** — від 3 до 60. Кожен запит має одну
  повторну спробу і TCP-fallback, коли UDP-відповідь обрізана
  (набори DNSKEY великі). Додатково весь обхід має спільний бюджет
  150 секунд, тож резолвер, який ковтає пакети, не може затягнути
  прогін понад 180-секундний таймаут маніфесту.

## Результат

- **Вкладка Results** — таблиця ланцюжка (зона · крок · ✓/✗ ·
  примітка) і звіт:
  - **Ланцюжок** — перевірка анкера, далі по зонах: отримання DS,
    валідація підпису DS, збіг DS↔DNSKEY, валідація DNSKEY. DS
    перераховується тим типом дайджесту, який оголошує сам запис DS
    (SHA-256, SHA-384 або SHA-1), тож зону, яка не використовує
    SHA-256, не буде помилково названо зламаною.
  - **Інвентар ключів** — кожен DNSKEY з тегом, роллю (KSK/ZSK),
    алгоритмом, бітами; RSA під 2048 бітів, RSA/SHA-1 і DSA —
    прапорець слабкості. У заголовку вказано, якій зоні ці ключі
    належать: коли ланцюжок обривається вище цілі (непідписана
    делегація, розрив), інвентар описує останню зону, що
    провалідувалася, а не ціль.
  - **Свіжість підписів** — найближчий термін RRSIG у днях, для тієї
    самої зони; менше 3 днів — попередження (зони з простроченими
    підписами стають bogus).
  - **NSEC/NSEC3** — з проби випадковим ім'ям: чи розкривають
    негативні відповіді список імен зони.
  - **Що означає вердикт** — абзац на кожен вердикт, включно з
    історією SERVFAIL для bogus і виправленням «опублікуйте DS» для
    signed-but-no-DS.
- **Артефакти** — `report.md`, `findings.json`.

## Коди виходу

| Код | Значення |
|---|---|
| 0 | відпрацювало; вердикт (будь-який із п'яти) — і є результат |
| 1 | резолвер не відповів узагалі — прогін не зміг початися |
| 2 | помилкові аргументи: не домен, резолвер не IP, timeout поза 3–60 |

Код 1 дає лише резолвер, який упав на найпершому запиті (кореневий
DNSKEY). Обрив ланцюжка нижче — це **результат**: прогін завершується
з кодом 0 і вердиктом 🔴 bogus чи ⚫ indeterminate, а звіт каже, де
саме він зупинився.
