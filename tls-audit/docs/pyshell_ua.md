# Аудит TLS

Оцінює TLS-шар хоста так само, як [**Security
Headers**](../../security-headers) оцінює HTTP-шар — два скрипти
аудитують дві половини одного ендпоінта, і їхні звіти свідомо
ідентичні за формою (бал 0–100, літерний грейд, таблиця знахідок із
конкретними виправленнями).

Аудит виконує **сім TLS-з'єднань** і не надсилає жодного HTTP-запиту:

1. сучасний хендшейк — зібрати сертифікат і те, що negotiatingься;
2. хендшейк із валідацією проти системного сховища довіри;
3–6. по одному хендшейку з фіксованою версією протоколу — TLS 1.0,
   1.1, 1.2, 1.3;
7. хендшейк TLS 1.2 із пропозицією *лише* слабких шифрів
   (NULL, EXPORT, DES, RC4, IDEA, анонімні).

Усе, що з'єднання дізнались, стає знахідкою: ланцюжок довіри,
відповідність hostname, строк дії, сила ключа, алгоритм підпису,
підтримка протоколів, слабкі шифри — кожна зі статусом, вагою в балі
та рекомендацією, яка є зміною конфігурації, а не мораллю.

---

## Перед запуском

1. **Host** — що завгодно, що іменує ендпоінт: `example.com`,
   `example.com:8443`, `https://example.com`. Схему і шлях
   ігноруються; порт за замовчуванням 443.
2. Натисніть **Prepare Env** — встановлювати нічого не треба, лише
   стандартна бібліотека.
3. Натисніть **Run** (⌘↩). Повний ран триває секунди; *Certificate
   checks only* — два з'єднання замість семи.

Сертифікат читається **навіть коли ланцюжок побитий** —
самопідписаний, прострочений чи невідповідний сертифікат — це саме
той, який аудит мусить усе одно описати, тому поля парсяться
безпосередньо з байтів сертифіката, а не з валідуючого хендшейку.

---

## Поля

### Target

- **Host** — TLS-ендпоінт. Голі IP теж працюють (SNI для них
  пропускається, як зробив би браузер).
- **Per-connection timeout (s)** — кожне з'єднання отримує стільки
  часу. Замовчування 10 с покриває повільні хендшейки; весь ран
  обмежений приблизно сімома такими таймаутами.
- **Certificate checks only** — пропустити проби протоколів і слабких
  шифрів. Два з'єднання замість семи; грейд тоді покриває лише
  сертифікат (ланцюжок, hostname, строк, ключ, підпис).

## Результат

- **Results tab** — заголовок із грейдом, таблиця знахідок (перевірка
  / статус / деталі / виправлення) та підсумок сертифіката з датами,
  ключем, підписом і SAN-ами — факти, які цитують у тикетах.
- **Артефакти** — `tls_raw.json` (усе зібране: узгоджена сесія,
  распарсені поля сертифіката, DER листка й ланцюжка, результат кожної
  проби), `findings.json` (бал, грейд, знахідки — машиночитабельно для
  CI), `report.md`.

### Що означають перевірки

| Перевірка | Pass | Fail |
|---|---|---|
| Ланцюжок довіри | валідується проти системного сховища | самопідписаний, відсутній інтермедіат, недовірений root — деталей — текст помилки валідації |
| Відповідність hostname | SAN (або легасі-CN) відповідає хосту | жодне ім'я в сертифікаті не покриває хост |
| Строк дії сертифіката | більше 30 днів запасу | прострочений, ще не чинний або ≤ 7 днів; ≤ 30 днів — warn |
| Тривалість сертифіката | ≤ 398 днів | понад 398 днів — поза лімітом публічної довіри (warn) |
| Публічний ключ | RSA ≥ 2048, EC ≥ P-256, Ed25519 | RSA < 2048 або EC < P-256 |
| Алгоритм підпису | SHA-256+ | SHA-1 або MD5 |
| TLS 1.0 / 1.1 | відмовлено | пропонується — deprecated з 2021 (RFC 8996) |
| TLS 1.2 | пропонується | не пропонується (warn — TLS 1.3-only сучасно, але відсікає старих клієнтів) |
| TLS 1.3 | пропонується | не пропонується (warn) |
| Слабкі шифри | відмовлено | сервер завершив хендшейк на NULL/EXPORT/DES/RC4/IDEA/anon-суїті |

Рядки «cannot probe» (коли локальний OpenSSL відмовляється, напр.,
пропонувати TLS 1.0 на стороні клієнта) **не оцінюються** — звіт
говорить це прямо і вказує на `nmap --script ssl-enum-ciphers` для
незалежного вердикту.

### Що цей інструмент свідомо не перевіряє

HTTP-заголовки (HSTS і компанія) — робота [Security
Headers](../../security-headers). OCSP stapling та TLS-ренегоціацію
модуль `ssl` Pythona не відкриває — коли перевірку неможливо зробити
чесно, її краще пропустити, ніж вгадати.

## Коди виходу

- `0` — ендпоінт досягнуто й перевірено. Грейд F — успішний аудит, що
  знайшов побитий TLS, а не помилка скрипта.
- `1` — ендпоінт взагалі недосяжний (DNS, відмова з'єднання,
  таймаут — провалився сам перший хендшейк).
- `2` — ціль не парситься як `host[:port]`.
