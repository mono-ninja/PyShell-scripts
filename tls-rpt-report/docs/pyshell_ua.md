# Звіт TLS RPT

Які ресивери не змогли підняти TLS до ваших MX. Шостий акт поштової
історії та близнюк «Звіту DMARC»: Email DNS Audit публікує політику
MTA-STS і адресу TLS-RPT (`_smtp._tls`), Mail Probe проходить вашим
власним TLS-дротом — а цей скрипт читає **зворотний зв'язок**:
звіти RFC 8460, які ресивери надсилають на ту адресу, коли не
змогли доставити вам пошту через TLS. Нікого не «пробують» —
інтернет уже відзвітував.

Вхід — те, що вже лежить у скриньці: `.json`, `.json.gz` та `.zip`
(кілька звітів в одному архіві — усі розпаковуються). Файли
зводяться в одну картину:

- **Типи збоїв** — `starttls-not-supported` (MX ресивера взагалі не
  запропонував TLS), `certificate-expired`,
  `certificate-not-trusted`, `validation-failure`,
  `sts-policy-invalid` (**зламана ваша власна политика**),
  `tls-version-insufficient` та інші — кожен зі своїми лічильниками
  і своїм значенням простими словами.
- **Ваші MX, яких торкнулися збої** — на які з ваших MX-імен
  цілили невдалі сесії.
- **MTA-відправники** — які IP зазнавали невдач, з лічильниками по
  типах.
- **Читання режиму** — у режимі `testing` збої — спостереження; у
  `enforce` кожен збій — **лист, який не доставлено**. Звіт каже, у
  якому світі ви перебуваєте.

Офлайн, лише стандартна бібліотека, нуль мережі — як «Звіт DMARC».

---

## Перед запуском

1. Збережіть вкладення звітів зі скриньки (вони приходять на адресу
   TLS-RPT `_smtp._tls` вашого домену — ту, яку налаштовує Email
   DNS Audit).
2. Оберіть **Source** — один файл, кілька або теку (рекурсивно з
   підтеками).
3. **Prepare Env** не потрібен — лише стандартна бібліотека.
   Натисніть **Run** (⌘↩).

## Поля

### Input

- **Source** — один / кілька / тека. Розширення: `.json`,
  `.json.gz`, `.zip`. Zip із кількома звітами розпаковується
  поелементно — кожен звіт входить у зведену картину. Файли іншого
  формату відмічаються як пропущені.
- **Report file** — один звіт (режим одного файла).
- **Report files** — звіти для зведення (режим кількох).
- **Report folder** — читаються всі звітоподібні файли цієї теки
  (режим теки).
- **Recursive (with subfolders)** — режим теки: заходити в підтеки.

---

## Результат

- **Вкладка Results** — таблиця типів збоїв (тип · кількість · що це
  означає) і звіт:
  - **Успіхи проти збоїв** — частка доставок через TLS.
  - **Типи збоїв** — кожен `result-type` з RFC 8460 із лічильником
    і зрозумілим поясненням; невідомі типи вказують на
    RFC 8460 §3.4 замість здогадок.
  - **Ваші MX** — імена ресиверів, за якими сталися збої.
  - **MTA-відправники** — IP за невдачами.
  - **Що означає режим** — testing чи enforce, розписано; збої
    `sts-policy-*` позначаються як **проблема на вашому боці
    дроту**.
- **Артефакти** — `report.md`, `findings.json` (лічильники за
  типами/IP/MX, режим, деталі по звітах, нечитані файли).

## Коди виходу

| Код | Значення |
|---|---|
| 0 | відпрацювало; звіт і є картина |
| 1 | жоден звіт не розпарсився |
| 2 | помилкові аргументи: не те розширення, немає файла, порожня тека |

## Пов'язане

- **Email DNS Audit** — запис MTA-STS і адреса `_smtp._tls`, на яку
  приходять ці звіти.
- **Mail Probe** — TLS-дріт ваших власних MX, з вашого боку.
- **Звіт DMARC** — близнюк-зворотний зв'язок про справжність
  відправника.
