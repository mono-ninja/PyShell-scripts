# HTTP Request

Надсилає один HTTP-запит і показує відповідь: статус, заголовки (з дублікатами),
тіло (JSON форматується, бінарні зберігаються як `response.bin`), таймінг
(з розщепленням TTFB / завантаження), кукі та еквівалентну команду `curl`.
Інтерактивний «відправити і подивитись».

Мережевий скрипт: PyShell не ізолює процес, тож запит йде напряму, з вашою
IP-адресою.

---

## Швидкий старт

1. Натисніть **Prepare Env** — PyShell встановить `requests`. Один раз.
2. **Method** = `GET`, **URL** = `https://jsonplaceholder.typicode.com/posts/1`.
3. Натисніть **Run**. У вкладці **Results** з'явиться відповідь: статус `200`,
   заголовки, тіло у вигляді JSON.

---

## Поля

### Request

- **Method** — HTTP-метод. `GET` за замовчуванням.
- **URL** — повна адреса зі схемою (`https://…`). Обов'язкове.
- **Query params** — необов'язкове. Параметри рядка запиту, зливаються з тим, що
  вже в URL. Два формати:
  - JSON-об'єкт: `{"page": "1", "size": "20"}`. Значення-список повторює ключ:
    `{"tag": ["a", "b"]}` → `?tag=a&tag=b`.
  - По одному `key=value` на рядок. Рядки з `#` ігноруються.
- **Headers** — необов'язкове. Два формати:
  - JSON-об'єкт: `{"Content-Type": "application/json", "Accept": "*/*"}`
  - По одному `Key: Value` на рядок. Рядки з `#` ігноруються.
- **Body** — тіло запиту. Якщо валідний JSON — надсилається як JSON (з
  відповідним `Content-Type`), інакше як сирий текст (за замовч. отримує
  `text/plain; charset=utf-8`, якщо ви не задали свій). Ігнорується для `GET`,
  `HEAD`, `OPTIONS`. Тіло, що виглядає як JSON (починається з `{` або `[`), але
  не парситься — помилка запуску (код 2).

### Auth

- **Bearer token** — секрет (зберігається в Keychain, передається через env,
  ніколи не потрапляє в argv чи лог). Підставляється як
  `Authorization: Bearer <token>`, якщо ви не задали свій `Authorization`.
- **Basic-auth user** — ім'я користувача для HTTP Basic auth.
- **Basic-auth password** — пароль (секрет, Keychain → env). Працює лише разом
  з **user**.

### Options

- **Timeout** — скільки чекати на відповідь, 1–90 с. Обмежено 90, щоб скрипт
  встиг записати артефакти до загального таймауту PyShell (120 с).
- **Max body bytes** — скільки байтів тіла відповіді прочитати в пам'ять
  (за замовч. 5 МБ). Більші відповіді обрізаються з позначкою `truncated`.
- **Follow redirects** — автоматично переходити за `3xx`. За замовч. увімкнено.
- **Skip TLS verification** — не перевіряти сертифікат сервера. Для staging і
  self-signed. У звіті з'являється попередження.
- **Redact secrets** — маскувати `Authorization`, `Cookie`, `Set-Cookie`,
  `X-Api-Key` у звіті та артефактах (значення замінюється на `•••• (N chars,
  redacted)`). Токен із Keychain все одно не потрапляє в argv, а цей перемикач
  ховає секрети з відповіді.
- **Repeat** — повторити запит N разів (1–50) і показати мінімум / медіану /
  максимум таймінгу. Корисно для оцінки стабільності латентності.
- **Verbose** — друкувати деталі запиту (заголовки, тіло) у лог.

## Приклад: POST-запит

1. **Method** = `POST`
2. **URL** = `https://jsonplaceholder.typicode.com/posts`
3. **Headers** = `{"Content-Type": "application/json"}`
4. **Body** =
   ```json
   {"title": "hello", "body": "world", "userId": 1}
   ```
5. **Run** → статус `201 Created`, відповідь із присвоєним `id`.

---

## Результати

- **Markdown** у вкладці Results — статус з reason-фразою (`200 OK`), таймінг
  (загальний + TTFB + завантаження), розмір (декодований і wire, якщо
  відрізняється), ланцюжок редиректів (якщо були), еквівалентна команда `curl`,
  таблиця заголовків (дублікати — окремими рядками), таблиця кукі, тіло.
  JSON-тіла форматуються з відступами; бінарні тіла замінюються рядком про тип і
  розмір; великі відповіді (понад 20 000 символів) обрізаються з приміткою.
- **Артефакти** у вкладці Files:
  - `request.json` — запит як його відправлено (метод, URL, заголовки, тіло,
    auth) — для відтворення;
  - `response.json` — машинно-читний запис: статус, таймінг, розмір, заголовки
    (плоский dict + `headers_multi` з дублікатами), кукі, кодування, тіло;
  - `response.txt` — сире тіло відповіді як текст (для текстових відповідей);
  - `response.bin` — сире тіло відповіді як байти (для бінарних: зображення,
    PDF тощо).

  При мережевій помилці (відповіді немає) `response.txt`/`response.bin` не
  створюються.

---

## Код виходу

- `0` — отримано відповідь (навіть `4xx`/`5xx` — це успішний запуск, відповідь
  є). Невдалий статус видно у звіті, не в коді.
- `1` — мережева помилка (таймаут, відмова з'єднання, DNS) — відповіді немає.
- `2` — не вдалося розібрати заголовки, параметри запиту або тіло запиту.

Тобто червоний рядок у History означає «запит не дійшов», а не «сервер
повернув помилку» — це різні речі.
