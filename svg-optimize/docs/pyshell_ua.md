# Оптимізація SVG

Мінімізує SVG-файли за допомогою [scour](https://github.com/scour-project/scour)
— один файл, кілька або ціла папка (за потреби рекурсивно). Контракт,
успадкований від [Image Optimizer](../../image-optimizer): **ніколи не
писати файл більший за вхід** — коли вихід scour вийшов би більшим,
оригінальні байти проходять далі без змін як `kept original`. Оригінали
ніколи не змінюються; усе потрапляє у вихідну папку.

Природний перед-крок перед [SVG Sprite — Build](../../svg-sprite-build):
спершу оптимізуйте іконки, потім збирайте їх у спрайт.

---

## Перед запуском

1. Оберіть **Source** — один SVG, кілька або папку (з перемикачем
   **Recursive** для підпапок; структура зберігається у виході).
2. Натисніть **Prepare Env** — встановить `scour`.
3. Оберіть **Output folder** і натисніть **Run** (⌘↩).

## Поля

### Input

- **Source** — один файл, кілька обраних файлів або папка.
- **Recursive** (режим папки) — обходити й підпапки.

### Optimize

- **Number precision (digits)** — десяткових знаків у координатах.
  5 (замовчування) лишає рендеринг ідентичним; 2–3 стискає шляхи
  сильніше з реальним, зазвичай невидимим, компромісом.
- **Strip metadata** — прибирає елемент `<metadata>`: сміття редакторів
  (Inkscape, Illustrator), що часто важить більше за сам малюнок.
  **`<title>` і `<desc>` зберігаються** — це доступність, а не баласт.
- **Strip comments** — XML-коментарі у файлі.
- **Strip XML prolog** — рядок `<?xml …?>`, зайвий для SVG, що
  віддається по HTTP; лишіть, якщо його хоче інструмент далі по ланцюгу.
- **Shorten IDs** — перейменовує довгі ID елементів на короткі. Більший
  виграш, але **ламає будь-які посилання на ці ID ззовні файлу** —
  тому вимкнено за замовчуванням.

### Output

- **Output folder** — куди пишуться оптимізовані копії. Оригінали
  ніколи не змінюються.
- **Overwrite existing** — коли вимкнено, файли, що вже є у вихідній
  папці, пропускаються (із звітом, не мовчки).

---

## Результат

- **Results tab** — таблиця по файлах (файл · статус · до · після ·
  зекономлено %) і підсумок: всього байт зекономлено, optimized /
  kept-original / skipped / error.
- **Артефакти** — `optimization_report.csv`: кожен рядок з розмірами,
  відсотком і приміткою, машиночитабельно.

### Як читати статуси

- **optimized** — вихід scour менший; копія у вихідній папці —
  мінімізована.
- **kept original** — вихід scour був рівний або більший (вже
  мінімізовано, або файл тонко налаштований вручну): копія байт-у-байт
  як вхід. Це запобіжник, а не помилка.
- **skipped** — файл з таким ім'ям вже є у вихідній папці, а
  **Overwrite existing** вимкнено.
- **error** — не читається або не пишеться; примітка каже, чому.

## Коди виходу

- `0` — партію оброблено; kept-original — це результати, а не помилки.
- `1` — нема що оптимізувати, scour не встановлено, вихідна папка
  непридатна, або кожен файл зазнав помилки.
- `2` — неправильні аргументи (відсутній вхід режиму, шлях не файл/папка,
  порожня папка).
