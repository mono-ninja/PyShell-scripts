# Аудит security-заголовків

Оцінює HTTP security-заголовки URL — HSTS, CSP, `X-Content-Type-Options`,
`X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, COOP, CORP, прапорці
кук, витоки версій — і повертає оцінку 0–100, літерний грейд (A+ … F) і
конкретні виправлення, готові вставити в конфіг сервера.

Пасивний за задумом: **один GET-запит** (або обмежений ланцюжок редіректів,
максимум 10 переходів), нічого такого, чого не викликає звичайний візит
браузера. Ніякого сканування чи фазингу.

---

## Перед запуском

1. Натисніть **Prepare Env** — встановить `requests`.
2. **URL** — сторінка для аудиту, зі схемою (`https://…`).
   Використовується `GET` (не `HEAD`): деякі сервери вішають CSP/HSTS лише на
   справжні document-відповіді, `HEAD` би занижив результат.

---

## Поля

### Запит

- **URL** — цільова сторінка.
- **Переходити за редіректами** (увімкнено за замовчуванням) — аудит всього
  ланцюжка. Набір заголовків фіксується **на кожному переході**: заголовок,
  який був на origin, але зник після редіректу на CDN-край, стає окремим
  файндингом — інструменти, що дивляться лише на фінальну відповідь, такого
  ніколи не побачать. Вимкніть, щоб аудитити рівно одну відповідь за URL.
- **Таймаут (с)** — на один запит; кожен перехід редіректу має свій бюджет.
- **User-Agent** — за замовчуванням ідентифікує скрипт як PyShell-аудит.
  Деякі WAF тихо дропають голий `python-requests`, що виглядає як таймаут.
- **Додаткові заголовки запиту** — по одному `Key: Value` на рядок.
  Використовуйте для аудиту сторінок за авторизацією (заголовок `Cookie`
  сесії); заголовок йде в *запит*, а не в оцінювання.
- **Не перевіряти TLS** — для внутрішніх/staging-хостів із самопідписаними
  сертифікатами.

---

## Що перевіряється

| Заголовок | Умова «pass» |
|---|---|
| `Strict-Transport-Security` | присутній, `max-age` ≥ ~6 місяців (`15768000`) |
| `Content-Security-Policy` | присутній, є `default-src` або повний набір `-src`-директив; без «голих» `unsafe-inline`/`unsafe-eval` |
| `X-Content-Type-Options` | рівно `nosniff` |
| `X-Frame-Options` | `DENY`/`SAMEORIGIN` — або CSP `frame-ancestors`, який його заміняє |
| `Referrer-Policy` | присутній, не `unsafe-url` |
| `Permissions-Policy` | присутній (інформаційна вага — більшість сайтів його ще не шле) |
| `Cross-Origin-Opener-Policy` | `same-origin` (інформаційна вага — новіший за Permissions-Policy, поширення ще нижче) |
| `Cross-Origin-Resource-Policy` | `same-origin` / `same-site` (інформаційна вага, та сама причина) |
| `Set-Cookie` | на кожну куку: `Secure` + `HttpOnly` + `SameSite` усі встановлені |
| `Server` / `X-Powered-By` | відсутні або без версії — витік версії не оцінюється, лише відмічається |

`X-XSS-Protection` отримує лише примітку, без оцінки: сучасна рекомендація —
взагалі не відправляти його (застарілий, і на старому IE міг сам створити
XSS-вектор).

## Результат

- **Вкладка Results** — markdown-звіт: грейд у заголовку, топ-3 виправлення,
  повна таблиця файндингів (Заголовок / Статус / Деталь / Виправлення) і
  ланцюжок редіректів.
- **Артефакти** — `headers_raw.json` (усі заголовки на кожному переході,
  дослівно — сирові докази), `findings.json` (машиночитний, для CI),
  `report.md`.

## Код виходу

- `0` — відповідь отримано, незалежно від грейду. `F` — це успішний аудит,
  який знайшов поганий результат, а не збій скрипта.
- `1` — відповіді взагалі немає (таймаут, connection refused, DNS).
- `2` — блок додаткових заголовків не парситься.

Червоний рядок у History означає «запит не долетів», а не «сайт отримав низьку
оцінку».
