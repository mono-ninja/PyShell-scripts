# SVG Sprite — Build

Збирає теку з `.svg`-іконок у один symbol-sprite (`sprite.svg`) — набір
`<symbol>`-визначень у одному прихованому `<svg>`, на який далі посилаються з
верстки через `<svg><use href="#icon-…"/></svg>`. Додатково може згенерувати
`catalog.html` (самодостатня сторінка-превʼю всіх іконок) та `sprite.php`
(WordPress-include з тими ж defs).

---

## Перед запуском

1. Натисніть **Prepare Env** — PyShell встановить `lxml`, `tinycss2`, `jinja2`.
2. **Icons folder** — тека з `.svg`. Рекурсії немає: підпапки ігноруються,
   приховані файли (крапка на початку) теж.
3. **Output folder** — куди писати артефакти, зазвичай десь усередині проєкту
   (`assets/icons/`). Sprite записується сюди, а під PyShell — ще й у теку
   артефактів, щоб зʼявились картки **Show**/**Save**.

---

## Поля

### Source

- **Icons folder** — єдина вхідна тека. Шляхи сортуються детерміновано (байтовий
  порядок), тож та сама тека дає байт-в-байт однаковий sprite — diff у git
  показує реальну зміну, а не переставлені рядки.

### Naming

- **Symbol ID prefix** — префікс для id кожного symbol (за замовч. `icon-`).
  Імʼя файлу slugifікується: нижній регістр, роздільники → `-`, префікс
  `icon-` з назви зрізається, потім знову додається ваш префікс. Тому
  `Arrow_Left.svg` і `icon-arrow-left.svg` обидва стануть `icon-arrow-left`.

### Normalize

- **Substitute currentColor** — вимкнено за замовч. Якщо увімкнути, scroll
  усі значення `fill`/`stroke` іконки; коли є рівно один не-`none` колір — він
  замінюється на `currentColor` (іконка бере колір з CSS `color`). Декілька
  кольорів (duotone) залишаються як є, у попередженнях зʼявиться «multicolour».
  Посилання на градієнти `url(#…)` кольорами не вважаються.
- **Add `<title>` from filename** — додає `<title>` зі slug-івки першою дитиною
  `<symbol>` (доступність). Редакторські `<title>`/`<desc>` завжди видаляються,
  цей прапорець лише перевмикає новий `<title>`.

Кореневі атрибути `fill`, `stroke`, `stroke-width`, `stroke-linecap`,
`stroke-linejoin`, `fill-rule` переносяться з вихідного `<svg>` на `<symbol>` —
це те, що рятує outline-набори (Lucide/Feather з `fill="none"`) від того, щоб
стати чорними плямами. `width`/`height` зрізаються — розміром керує CSS.

### Optimize

- **Path precision** — кількість знаків після коми, до якої округлюються числа
  в `d` (path) та `points` (polygon/polyline). `3` за замовч. `0` — цілі.
- **Run npx svgo pre-pass** — прогнати джерела через SVGO перед збиранням.
  Потрібен Node/npx. Це єдиний спосіб серйозного стиснення (злиття шляхів,
  колапс трансформів) — усередині скрипт їх не повторює. За будь-якої помилки
  (svgo не встановлено, таймаут) прогін просто йде на оригіналах, без аварії.

Оптимізація всередині навмисно консервативна: прибирає коментарі та
`<metadata>`, порожні `<g>`, невикористані діти `<defs>`, атрибути що дорівнюють
SVG-замовчуванням (тільки коли жоден предок не задає ту ж властивість — щоб
явне `stroke="none"`, що перевизначає успадкований `stroke="red"`, не зникло).

### Output

- **Generate catalog.html** — увімкнено за замовч. Самодостатня HTML-сторінка:
  sprite вбудовано всередину (приховано), кожна іконка рендериться через
  `<use href="#id">`. Працює з `file://`.
- **Generate WordPress include (sprite.php)** — sprite-defs як PHP-файл.
  `<?php include 'sprite.php'; ?>` виведе прихований `<svg>` з усіма symbol;
  далі у верстці `<use href="#icon-…">`.

## Дедуплікація id та класів

Кожен `id` усередині іконки отримує префікс `{symbol-id}__`, і кожне
посилання на нього переписується — `href="#a"`, `url(#a)` у `fill`/`stroke`/
`clip-path`/`mask`/`filter`/`marker-*`, у `style`-атрибутах та у CSS всередині
`<style>`, а також `id.event` у `begin`/`end` анімацій. Класи префіксуються
так само, селектори в `<style>` переписуються через `tinycss2`. Це те, чому
Illustrator-івський `.st0 { fill:#000 }` не перевизначить усі інші іконки спрайту.

## Код виходу

- `0` — sprite збудовано (навіть якщо частину файлів пропущено: битий SVG,
  чи іконка без `viewBox` — вони лишаються у таблиці з попередженням).
- `1` — не знайдено жодного `.svg`.
- `2` — помилка аргументів, або **конфлікт імен** (A3): два файли slugifікуються
  в однаковий id (наприклад `arrow_left.svg` і `arrow-left.svg` у одній теці).
  У повідомленні названо обидва шляхи — це жорстка помилка, бо sprite не може
  вмістити два symbol з тим самим id. Один битий експорт таку помилку не дає —
  бачите це у History як зелений запуск із попередженнями, а не як червоний.
