# Генератор сайтмапу

Будує `sitemap.xml` для пошукових систем зі `site_snapshot.json`, який
створює окремий скрипт [**Site Crawler**](../../site-crawler) — остання
ланка пайплайна *кравлити → перевірити → полагодити*, серединкою якого
є [**SEO Checks**](../../seo-checks).

У сайтмап потрапляють лише URL, що проходять планку обіцянки сайтмапу:
справді завантажені, живі, індексовані, канонічні, на хості цього сайту.
Усе інше виключається **з причиною** — noindex-сторінки, джерела
редіректів, неканонічні дублікати, сторінки заблоковані robots.txt,
чужі хости, биті посилання — і кожне виключення потрапляє у
`sitemap_excluded.csv`. Сайтмап, який можна перевірити, — це сайтмап,
якому можна довіряти; інакше це файл, за який сподіваюшся.

Без мережі: снапшот — єдине джерело даних, нічого не завантажується,
сайт не чіпається.

---

## Залежності

Потребує [**Site Crawler**](../../site-crawler) (`com.pyshell.sitecrawler`):

1. Запустіть Site Crawler на сайті — він збереже `site_snapshot.json`
   (виберіть output-папку, щоб файл пережив ран)
2. Вкажіть цей файл у полі **Site snapshot** цього скрипта

Без Site Crawler генерувати нізвідки — снапшот єдине джерело даних, у
ньому статус, canonical та robots-сигнали кожної сторінки.

---

## Перед запуском

1. Спершу проскануйте сайт [Site Crawler-ом](../../site-crawler).
   Версія `schema` снапшота перевіряється; невідома — відхиляється з
   зрозумілим повідомленням. Старіші схеми завантажуються, але чесно
   кажуть, чого їм бракує: schema 2+ несе заголовки відповіді (половина
   визначення noindex через `X-Robots-Tag`) та hreflang; schema 5+ —
   `lastmod` попереднього сайтмапу для кожної сторінки (використовує
   режим *preserve*).
2. Натисніть **Prepare Env** — встановлювати нічого не треба, скрипт
   працює лише на стандартній бібліотеці.
3. **Site snapshot** — виберіть файл `site_snapshot.json`.

**Обірваний (capped/partial) кравл відхиляється** (exit 1). Сайтмап,
збудований з неповного кравлу, мовчки викидає всі URL, до яких кравл не
дійшов, — а деплой такого файлу поверх робочого сайтмапу прибрав би їх
з нього. Перекравліть без ліміту, або — коли пропуск вам зрозумілий —
увімкніть *Generate even from a capped/partial crawl*. Та сама відмова,
з тією ж причиною, спрацьовує, коли **нічого не кваліфікувалось**:
порожній сайтмап поверх робочого викидає весь сайт.

---

## Поля

### Input

- **Site snapshot** — `site_snapshot.json` від Site Crawler.
- **Generate even from a capped/partial crawl** — вимкнено за
  замовчуванням. Коли снапшот позначено `capped` (досягнуто ліміту
  сторінок/глибини) або `partial` (зупинено достроку), запуск
  відмовляється, замість того щоб будувати сайтмап, який мовчки
  пропустить сторінки. Увімкніть, лише якщо пропуск прийнятний; у
  звіті все одно буде помітне попередження.

### Filters

- **Only include URLs matching this path glob** — напр. `/blog/*`, щоб
  побудувати сайтмап для одного розділу. В формі — один шаблон; з
  терміналу можна передати кілька `--include-path`.
- **Skip URLs matching this path glob** — напр. `/tag/`, щоб лишити
  розділ поза сайтмапом. Так само один шаблон у формі.

### Content

- **lastmod source** — що потрапляє в кожен `<lastmod>`:
  - *Preserve* (замовчування) — зберегти `lastmod`, який для цього URL
    ніс *попередній* сайтмап сайту (потрібен снапшот schema 5+,
    зібраний з `--use-sitemap`), з відкатом на час кравлу. Збереження
    тримає дати чесними: перегенерований сайтмап не стверджує, що
    кожна сторінка змінилась сьогодні.
  - *Crawl time* — коли Site Crawler завантажив сторінку.
  - *None* — повністю опустити `<lastmod>`.
- **Skip hreflang alternates** — вимкнено за замовчуванням. Кожен
  запис зазвичай несе hreflang-мапу сторінки як рядки
  `<xhtml:link rel="alternate">` — саме так багатомовні сайти й
  мають це робити. Пропускайте, лише якщо hreflang подається іншим
  шляхом (наприклад, HTTP-заголовками).

### Output

- **Write artifacts here too** — реальна проєктна папка, щоб
  `sitemap.xml` пережив ран. Без неї артефакти пишуться поруч зі
  снапшотом та в робочу папку PyShell.

## Результат

- **Results tab** — таблиця розподілу (скільки URL включено, скільки
  виключено за кожною причиною), стовпчикова діаграма того ж, і повний
  звіт: попередження, кожне виключення згруповане за причиною з
  названою ціллю, та інструкція з розгортання.
- **Артефакти**:
  - `sitemap.xml` — сайтмап. Понад 50 000 URL він стає
    `<sitemapindex>` плюс частини `sitemap-1.xml` … (рядок для
    robots.txt і всі закладки подання продовжують вказувати на
    `sitemap.xml`).
  - `sitemap_excluded.csv` — рядок на кожен виключений URL: сам URL,
    код причини, ціль, якщо є. Аудит-трейл.
  - `report.md` — той самий звіт, що й у Results tab.

`changefreq` та `priority` свідомо не пишуться — пошуковики їх
ігнорують, а їхня відсутність тримає файл чесним.

---

## Коди виходу

- `0` — сайтмап згенеровано. Виключення — це результат, а не помилка:
  30% сайту в `noindex` — успішний ран із знахідкою.
- `1` — снапшот не читається або схема невідома; кравл був
  capped/partial без дозволу; нічого не кваліфікувалось (`sitemap.xml`
  у цьому випадку не пишеться — звіт і CSV таки пишуться); або
  артефакти неможливо записати.
- `2` — неправильні аргументи.
