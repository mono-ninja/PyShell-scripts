# Аналіз HAR

Що на цій сторінці справді важке — `.har` із DevTools, прочитаний
**офлайн** стандартною бібліотекою, як діагноз: waterfall по фазах
(dns/connect/ssl/wait/receive, агреговано), ресурси, що блокують
рендер (стилі за визначенням; скрипти, які збережений документ
вантажить без async/defer — чесно «не визначити», коли контент не
збережено), інвентар третьої сторони по реєструємих доменах з
байтами, розмір за типами, що віддано з кешу (memory/disk/304),
ланцюжки редіректів і найгірші 10 запитів з розкладом по фазах.

Лінія продуктивності, закрита з боку браузера: Server Timing (один
URL, живцем) · Cache Check (шар кешу) · Load Test (деградація) ·
**цей** (що браузер фактично завантажив).

---

## Перед запуском

1. У DevTools → Network: завантажте сторінку, потім *Save all as
   HAR with content* — відповіді в архіві розблоковують аналіз
   блокування рендеру.
2. Оберіть **HAR file**.
3. **Prepare Env** не потрібен — лише стандартна бібліотека.
   Натисніть **Run** (⌘↩).

## Поля

### Input

- **HAR file** — експорт із DevTools (будь-який браузер; формат
  спільний).
- **Max entries** — запобіжний ліміт (100–50000, типовo 5000);
  більший HAR обрізається з приміткою у звіті.

---

## Результат

- **Вкладка Results** — таблиця найгірших 10 (url · мс · тип ·
  розмір · ttfb · receive), стовпчикова діаграма розміру за
  типами, і звіт:
  - **Куди пішли мілісекунди** — кожна фаза сумарно і в середньому
    по запитах, де вона є.
  - **Вага за типами** — кошики з кількостями і частками.
  - **Третя сторона** — скільки сторінки приходить з інших
    реєструємих доменів, топ-10 за байтами; піддомени домена
    сторінки не рахуються.
  - **Блокування рендеру** — кількість стилів; синхронно вантажені
    скрипти поіменно (зі збереженого документа); без контенту —
    чесна примітка.
  - **З кешу** — memory × / disk × / revalidated × з байтами, які
    не покидали origin.
  - **Редіректи** і **найгірші 10**.
- **Артефакти** — `report.md`, `har_findings.json` (усе,
  машиночитно).

## Коди виходу

| Код | Значення |
|---|---|
| 0 | відпрацювало; звіт і є діагноз |
| 1 | не HAR (нема `log`), кривий JSON або нуль записів |
| 2 | помилкові аргументи: немає файла |

## Пов'язане

- **Server Timing** — та сама математика фаз, живцем, для одного
  URL.
- **Cache Check** — шар кешу, попадання з якого рахує цей звіт.
- **Tech Stack** — інвентар третьої сторони з боку технологій; цей
  звіт показує його вартість у байтах.
