# Мапа редіректів

Пропущена ланка між зниклими URL від Wayback Check і аудитом
ланцюжків у SEO Checks: старі URL, зіставлені зі свіжим знімком
Site Crawler, з **рівнем впевненості для кожного рядка** — скрипт
*пропонує* мапу, він ніколи не видає свою пропозицію за
правильну відповідь.

Входи:

- **Old URLs** — `wayback_vanished.csv` від Wayback Check, старий
  знімок Site Crawler (`.json` — його живі сторінки, яких більше
  нема, стають кандидатами) або простий список по одному URL на
  рядок.
- **Свіжий знімок** — `site_snapshot.json` Site Crawler про сайт
  таким, як він є зараз.

Драбина зіставлення, по кожному старому URL:

1. **Точний** — нормалізований шлях існує в новому знімку (регістр,
   кінцевий слеш, суфікси `.html`/`index` згорнуті): впевнено.
2. **Слаг** — останній сегмент шляху збігається точно
   (`/blog/post/` → `/posts/post/`): впевнено, класичний хід
   міграції.
3. **Нечіткий** — схожість слага чи заголовка ≥ 0.80: **потребує
   перегляду**, з балом і тим, що саме збіглося.
4. Нічого не подолало планку: **не знайдено** — мапа не може
   вигадати ціль; 410 Gone — чесний варіант для справді зниклих.

Якщо не пропущено, кожен запропонований редірект **перевіряється
живим запитом**: чи приземляється 301 → 200, без ланцюжків
(редірект → редірект) і петель — а 404 названі *очікуваними, поки
мапу не встановлено*, що рівно те й міряє перший ран.

---

## Залежності

Потребує [**Site Crawler**](../../site-crawler)
(`com.pyshell.sitecrawler`):

1. Запустіть Site Crawler на сайті таким, як він є зараз — він
   запише `site_snapshot.json` (оберіть теку виводу, щоб файл
   пережив ран)
2. Вкажіть цей файл у полі **New snapshot**

**Old URLs** приходять звідти: `wayback_vanished.csv` від Wayback
Check (запустіть його на тому ж домені), старий знімок Site Crawler
зберігся з часів до міграції, або простий список. Без Site Crawler
немає свіжої сторони для зіставлення — скрипт не може відпрацювати.

## Перед запуском

1. Прокраульте сайт зараз (Site Crawler), збережіть знімок.
2. Зберіть старі URL (Wayback Check / старий знімок / список).
3. Натисніть **Run** (⌘↩). **Prepare Env** один раз ставить
   `requests`.

## Поля

### Input

- **Old URLs** — джерело зниклих URL: `wayback_vanished.csv`
  (його колонка `url`), старий `site_snapshot.json` (його живі
  сторінки стають кандидатами) або `.txt` по одному URL на рядок
  (коментарі `#` дозволені).
- **New snapshot** — свіжий `site_snapshot.json`; його живі
  сторінки — цілі редіректів.

### Verification

- **Skip live verification** — вимкнено за замовчуванням:
  кожен запропонований редірект перевіряється живим запитом (один
  GET, редіректи простежуються вручну: 301 → 200, ланцюжки й петлі
  названі). Пропустіть для чисто офлайн-проходу по двох файлах.
- **Per-request timeout (s)** — дедлайн на запит, 3–60 (за
  замовчуванням 15).

## Результат

- **Вкладка Results** — таблиця рядків (старий → новий ·
  впевненість · жива перевірка) і звіт: впевнені збіги з причинами,
  пропозиції на перегляд з балами, ненайдені рядки з порадою 410,
  рядки «досі існує», виключені з мапи.
- **Артефакти** —
  - `redirect_map.conf` — сніпет nginx `map $uri` (збереження
    query у `return`; рядки на перегляд закоментовані),
  - `redirect_map_htaccess.txt` — близнюк для Apache
    (`Redirect 301`),
  - `redirect_map.csv` — старий, новий, рівень, бал, жива
    перевірка — редагуйте, сперечайтеся, запускайте знову,
  - `findings.json`, `report.md`.

Контракт чесності, дослівно: **зіставлення евристичне**. Впевнені
рядки збіглися точним нормалізованим шляхом або точним слагом;
рядки на перегляд подолали планку схожості і є пропозиціями.
Скрипт пропонує мапу — ви її підтверджуєте.

## Коди виходу

| Код | Значення |
|---|---|
| 0 | відпрацювало; рівні впевненості — це результат («не знайдено» — знахідка, не збій) |
| 2 | помилкові аргументи: нечитаєме джерело, немає колонки `url`, не знімок |

## Пов'язане

- **Wayback Check** — звідки беруться зниклі URL.
- **Site Crawler** — свіжий знімок, з яким зіставляється мапа.
- **SEO Checks** — аудит ланцюжків/канонікал після встановлення
  мапи.
