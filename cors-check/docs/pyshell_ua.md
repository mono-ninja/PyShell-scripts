# Перевірка CORS

Чи політика CORS справді сувора — серія GET/OPTIONS-запитів із
**підробленим Origin** стежить за: відображенням атакувального
origin (критично з credentials), прийнятим null-origin,
wildcard-плюс-credentials, пастками префіксного/суфіксного/підрядкового
матчингу (баги `indexOf`/незаякорених регулярок), ехом preflight і
відсутнім `Vary: Origin`, яким живиться отруєння кешу.

Глибокий розбір за рядком CORS у Security Headers. Без
ownership-гейта: кілька звичайних запитів з одним кастомним
заголовком — трафік, який генерує будь-який браузер; нічого не
фазиться, пейлоадів не шлється.

---

## Перед запуском

1. Введіть **URL** ендпоінта для проби.
2. **Prepare Env** — встановлює `requests`.
3. Натисніть **Run** (⌘↩).

## Поля

### Target

- **URL** — API-ендпоінт або сторінка. Пастки конфузних origin
  будуються з цього хоста: `host.attacker.io`,
  `not-really-domain.com`, `domainattacker.io`.
- **Per-request timeout (s)** — 3–60, типовo 15.

---

## Результат

- **Вкладка Results** — таблиця (перевірка · результат ·
  серйозність · деталь) і звіт:
  - **Базова лінія** — що ендпоінт відповідає взагалі без Origin
    (ACAO, credentials, Vary).
  - **reflection** — атакувальний origin (`attacker.example`)
    відображений? З credentials → критично; без → високо.
  - **null origin** — `Origin: null` прийнятий (sandboxed iframe-и
    та `file://`-сторінки всередині межі довіри).
  - **wildcard(+credentials)** — `*` норм для публічних даних,
    хибно для всього пер-користувацького; `*` + credentials —
    підпис зламаного конфіґа.
  - **суфіксна / префіксна / підрядкова пастки** — конфузні origin
    з хоста самої цілі; прийнята пастка означає, що whitelist
    матчить по рядку, а не по домену.
  - **preflight** — OPTIONS + `Access-Control-Request-Method`:
    методи `*` = ворота відкриті для кожного дієслова.
  - **vary** — відповідь із відображенням без `Vary: Origin` =
    спільний кеш може прибити ACAO одного відвідувача до копії
    всіх.
- **Артефакти** — `report.md`, `findings.json`.

### Вердикти

🔴 reflected + credentials · 🟠 misconfigured · 🟡 loose but
guarded · 🟢 strict. Серйозність по кожній перевірці — у таблиці;
звіт завершується тим, як відповідає сувора CORS-конфігурація
(exact-origin whitelist, credentials ніколи з `*`, матчинг доменів
парсингом, а не підрядком).

## Коди виходу

| Код | Значення |
|---|---|
| 0 | відпрацювало; звіт і є картина |
| 1 | недосяжно — з'єднання не встановилося |
| 2 | помилкові аргументи: URL без http(s) |

## Пов'язане

- **Security Headers** — оцінки за наявність заголовків (його рядок
  CORS — це те, що цей скрипт розбирає вглиб).
- **CSP Audit** — та сама форма глибокого розбору для заголовка
  Content-Security-Policy.
- **Cache Check** — сторона Vary/origin у поведінці кешу.
