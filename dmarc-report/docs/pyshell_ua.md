# Звіт DMARC

Що бачить увесь інтернет у вашій пошті: агрегатні **RUA-звіти**
(`.xml`, `.xml.gz`, `.zip`-бандли — кілька звітів в одному архіві,
усі розпаковуються) від кожного ресивера, зведені в одну картину.
По кожному IP-джерелу: обсяг і власний вердикт ресивера
(`policy_evaluated` — без домислів), вирівняні SPF/DKIM, диспозиції.
Розділення форвардери/спуфінг: конверт-домен ≠ ваш, а DKIM-підпис
пережив хоп = переслана легітимна пошта; нуль вирівняних проходів =
кандидати в спуфінг. Головне — відсоток вирівняних проходів і
готовність домену до `p=none → quarantine → reject`.

Офлайн за замовчуванням; `--resolve-ptr` — єдина мережева дія, і вона
опційна.

---

## Перед запуском

1. Збережіть вкладення звітів зі скриньки (вони приходять на адресу
   `rua=` з вашого DMARC-запису).
2. Оберіть **Source** — один файл, кілька або теку (рекурсивно з
   підтеками).
3. **Prepare Env** не потрібен — лише стандартна бібліотека.
   Натисніть **Run** (⌘↩).

## Поля

### Input

- **Source** — один / кілька / тека. Розширення: `.xml`, `.xml.gz`,
  `.zip`. Zip із кількома звітами розпаковується поелементно —
  кожен звіт входить у зведену картину. Файли іншого формату
  відмічаються як пропущені.
- **Recursive (with subfolders)** — режим теки: заходити в підтеки.

### Analysis

- **Resolve source hostnames (PTR)** — вимкнено за замовчуванням.
  Коли ввімкнено: кожен IP-джерело отримує reverse-DNS запит —
  єдина мережа, яку цей скрипт взагалі робить; без неї все офлайн.

---

## Результат

- **Вкладка Results** — таблиця джерел (IP · повідомлень · DMARC
  pass % · spf aligned · dkim aligned · disposition) і звіт:
  - **Готовність** — ≥99% вирівняних → ready for p=reject; ≥95% →
    ready for p=quarantine; нижче → stay at p=none, з названим
    обсягом невдач і що виправляти (селектори, ARC для форвардерів).
  - **Джерела** — кожен IP з його вердиктами.
  - **Форвардери — невдачі, які не спуфінг** — конверт-домен
    інший, DKIM-підпис вцілів: розсилки й фільтр-сервіси; причина,
    з якої існує arc-sealing.
  - **Кандидати в спуфінг — нуль вирівняних проходів** — те, що
    заблокував би p=reject.
- **Артефакти** — `report.md`, `findings.json` (джерела,
  форвардери, кандидати, статус по кожному звіту).

## Коди виходу

| Код | Значення |
|---|---|
| 0 | відпрацювало; звіт і є картина |
| 1 | жоден звіт не розпарсився |
| 2 | помилкові аргументи: не те розширення, немає файла, порожня тека |

## Пов'язане

- **Email DNS Audit** — запис, який ресивери оцінюють
  (SPF/DKIM/DMARC як опубліковано).
- **Mail Header Check** — розбір одного збереженого листа (чому
  *цей* лист потрапив у спам).
- **Mail Probe** — дріт, яким говорять ваші сервери.
- **DNSBL Check** — репутаційні списки.
