# Аудит залежностей

Відомі вразливості у власних залежностях проєкту — **зафіксовані**
версії з лок-файлів, звірені з OSV (безкоштовно, без ключа,
батчами): requirements.txt (`==`-піни; діапазони чесно у список
*не зафіксовано, не перевірено*), poetry.lock, package-lock.json,
yarn.lock, pnpm-lock.yaml, composer.lock, go.mod, Gemfile.lock,
Cargo.lock. ID рекомендацій, CVE-аліаси і найближча виправлена
версія по кожній залежності.

Третій погляд на те саме дерево: secret-scan (креденшели), wp-audit
(ваш код), **цей** (чужий код з відомими дірками).

---

## Перед запуском

1. Оберіть **Project folder** — кожен підтримуваний лок-файл у ній
   (і один рівень підтек для монорепо; **Рекурсивно** обходить усе
   дерево, пропускаючи node_modules/.git/vendor).
2. **Prepare Env** — встановлює `requests` і `pyyaml`.
3. Натисніть **Run** (⌘↩).

## Поля

### Target

- **Project folder** — тека з лок-файлами. Нічого не модифікується;
  лок-файли лише читаються.
- **Max dependencies** — запобіжний ліміт (10–20000, типовo
  3000); досягнення позначає аудит як частковий.
- **OSV request timeout (s)** — кожен батч і кожен запит
  рекомендації отримує стільки часу.

---

## Результат

- **Вкладка Results** — таблиця (залежність · версія · vulns ·
  fix) і звіт:
  - **Вразливі залежності** — ID рекомендацій з CVE-аліасами і
    найменшою виправленою версією серед рекомендацій (`fix ≥ X`),
    посилання на сторінки OSV; відсутність виправленої версії
    сказано як є.
  - **Перепис по лок-файлах** — екосистема, кількість зафіксованих,
    незафіксованих, помилки читання.
  - **Не зафіксовано, не перевірено** — діапазони з
    requirements.txt: у діапазона нема однієї версії, за яку можна
    відповісти; перелічено, не вгадано (гадка «найгіршої з
    діапазону» була б шумом).
- **Артефакти** — `report.md`, `findings.json` (машиночитний
  список вразливих + список незафіксованих).

### Чесні межі

- Батч-відповіді slim за дизайном — деталі рекомендацій (аліаси,
  fix-діапазони) довантажуються по ID, паралельно, з лімітом 200;
  понад ліміт fix звітується як невідомий, замість того щоб
  розтягувати аудит на години.
- Залежності npm дедуплікуються між трьома форматами; зафіксована
  в двох лок-файлах залежність запитується один раз.

## Коди виходу

| Код | Значення |
|---|---|
| 0 | відпрацювало; знахідки — результат |
| 1 | нема підтримуваного лок-файла, лок-файли парсяться в ніщо, або OSV недосяжний |
| 2 | помилкові аргументи: не тека |

## Пов'язане

- **cve-check** — форма живого сайту: знімок tech-stack → той самий
  OSV.
- **wp-vuln-check** — WP-кут, якого OSV не покриває.
- **secret-scan / wp-audit** — інші два погляди на те саме дерево.
