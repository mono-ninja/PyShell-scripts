# Перевірка SRI

Чий код виконується на вашій сторінці і чи він закріплений
хешем. CSP Audit читає політику; цей скрипт читає самі теги
`<script>` і `<link rel=stylesheet>` — **вигляд ланцюга
постачання** однієї сторінки:

- **Сторонні ресурси без integrity** — те, що віддає CDN, те й
  виконується на вашій сторінці. Polyfill.io у червні 2024
  розіслав малвер половині мільйона сайтів; жодному з них не
  знадобилась нова вразливість — каналом доставки *була*
  вразливість.
- **Integrity без crossorigin** — хеш для cross-origin ресурсу
  перевіряється лише в CORS-режимі; без атрибута браузер взагалі
  відмовляється завантажити ресурс. Зламаний тег, не «м'яке
  попередження».
- **Помилка same-origin** — integrity на власних файлах зайве *і*
  блокує ресурс у день, коли деплой його перепише. SRI — для
  ресурсів, якими ви не керуєте.
- **Верифікація хешів** — кожен заявлений integrity-хеш звіряється
  з байтами, що віддаються *прямо зараз*: збіг, розбіжність (файл
  змінився — деплой-дрейф чи підробка) або чесно «не перевірено».
- **Готові теги** — для кожного незакріпленого стороннього ресурсу
  повний рядок `integrity="sha384-…" crossorigin="anonymous"`,
  обчислений із сьогоднішньої відповіді.

Один фетч сторінки + по одному на кожен унікальний ресурс (можно
пропустити режимом **Лише атрибути** — один запит загалом).

---

## Перед запуском

1. Знайте сторінку, яку хочете перевірити (одна URL — як Page SEO
   Audit, без краулінгу).
2. Натисніть **Run** (⌘↩). **Prepare Env** один раз ставить
   `requests`.

## Поля

### Target

- **Page URL** — сторінка, чий теги скриптів і стилів
  перевіряються. Кожен унікальний ресурс далі фетчиться один раз:
  верифікувати заявлений хеш або обчислити новий.
- **Per-request timeout (s)** — дедлайн на один запит, 3–60 (за
  замовчуванням 15).

### Mode

- **Attributes only (no resource fetches)** — прочитати теги, не
  звантажуючи жодного ресурсу: рівно один запит загалом, без
  верифікації хешів і без готових тегів. Знахідки рівня атрибутів
  (не закріплено, бракує crossorigin, невалідні хеші) працюють і
  так.

---

## Результат

- **Вкладка Results** — таблиця ресурсів (ресурс · тип · бік ·
  integrity · вердикт) і звіт:
  - **Інвентар хостів** — кожен хост за тегами: ваш origin / той
    самий сайт, інший origin / сторонній, з покриттям закріплень.
  - **Червоне — виправити** — незакріплені сторонні, integrity без
    crossorigin, невалідні хеші, розбіжності хешів.
  - **Жовте — на розсуд** — integrity на same-origin,
    `use-credentials` на CDN.
  - **Готові теги** — повні теги з сьогоднішнім sha384 і чесно
    сказаним компромісом: закріплений файл CDN, який змінився,
    ламає сторінку. Закріплюйте версионовані URL.
- **Артефакти** — `report.md`, `findings.json` (кожен ресурс з
  атрибутами, знахідками, станом хеша, сніпетом).

Лінія чесності: хеш, який збігся, означає *збіг прямо зараз* — не
«безпечно назавжди». І хеш закріплює файл таким, яким його віддано
в цей момент; коли CDN його оновить, сторінка ламається — і це
спроєктовано так навмисно.

## Коди виходу

| Код | Значення |
|---|---|
| 0 | відпрацювало; знахідки — це результат |
| 1 | сторінка недосяжна / відповіла не-200 |
| 2 | помилкові аргументи (не повна http(s) URL) |
