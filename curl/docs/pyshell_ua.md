# cURL

Обгортка навколо системного `curl`: форма збирає прапорці, скрипт будує команду,
виконує її й показує звіт — команду, статус, заголовки й тіло відповіді.

Використовує справжній бінарник `curl` із `PATH` (в macOS він є з коробки).
**Python-залежностей немає** — лише стандартна бібліотека. Файл `requirements.txt`
не потрібен.

## Групи полів

| Група | Що містить |
| --- | --- |
| **Request** | URL, метод, тіло (з кодуванням raw/binary/json/urlencoded), заголовки, User-Agent, Referer, `-i`/`-I`/`-f` |
| **Connection** | Таймаути, redirects, retries, стискання, версія HTTP (1.0–3), IPv4/IPv6, interface |
| **TLS** | `-k`, клієнтський сертифікат + ключ, CA, ciphers, макс. версія TLS |
| **Auth** | Basic / NTLM / Negotiate / Anyauth + окремий Bearer token. Паролі — тип `secret` → Keychain |
| **Proxy** | `--proxy`, ім'я користувача + пароль (`secret`), `--noproxy` |
| **Cookies** | `-b` (надіслати), `-c` (зберегти) |
| **Output** | `-s`/`-S`/`-v`, `-w`, `--dump-header`, зберегти тіло як артефакт |
| **Advanced** | `--resolve`, `--connect-to`, DNS-сервери, DNS-over-HTTPS, Unix-socket, keep-alive |

## Секрети

Поля **Password**, **Bearer token** і **Proxy password** мають тип `secret` —
значення зберігається в macOS Keychain і передається скрипту через змінну
оточення.

Далі скрипт **не кладе їх у командний рядок узагалі**. Замість `-u user:pass`
він формує конфіг curl і передає його через stdin (`curl -K -`), тож `ps` не
бачить креденшелів навіть у мить запуску. У звіті та в `command.sh` вони
показані як `***`:

```sh
curl -s -K - 'https://api.example.com/' <<'CURLRC'
user = "admin:***"
header = "Authorization: Bearer ***"
CURLRC
```

Підставте справжні значення замість `***` — і команду можна виконати в терміналі
як є.

**Bearer token не залежить від Auth method.** Це просто заголовок
`Authorization`, тому поле завжди видиме й працює як окремо, так і поверх
обраного методу.

Додатково маскуються: значення cookie в `-b` (імена лишаються видимими) і
заголовки `Authorization`, `Proxy-Authorization`, `X-Api-Key`, `Api-Key`,
`X-Auth-Token`, `X-Csrf-Token`, якщо ви вписали їх руками в поле **Headers**.

## Заголовки відповіді

Щоб звіт містив заголовки, curl має їх окремо зберегти. Якщо ви не обрали
`-i`, `-I` або `--dump-header`, скрипт автоматично додає `--dump-header` у
тимчасовий файл — заголовки завжди є у звіті. Цей службовий прапорець у звіті
не показується, бо ви його не задавали.

Коли ввімкнено **Follow redirects**, у звіт іде **остання** відповідь ланцюжка,
а не перший 301 — і для `-i`, і для `--dump-header` однаково.

## Що варто знати про окремі поля

- **Method: HEAD** надсилається як `-I`. Голий `-X HEAD` змушує curl чекати тіло,
  якого сервер не надішле, — запит просто висів би до таймауту.
- **HTTP version** розкладається на справжні прапорці curl (`--http1.1`,
  `--http2`, `--http2-prior-knowledge`, `--http3`). HTTP/3 працює лише якщо ваш
  curl зібраний з його підтримкою.
- **DNS servers** вимагає libcurl, зібраного з c-ares. Системний curl у macOS
  таким не є — тоді поле пропускається, а у звіті з'являється примітка. Для тих
  самих задач є **DNS-over-HTTPS** і `--resolve`.
- **Write-out** (`-w`) виводиться в окрему секцію звіту, а не домішується до
  тіла, тож артефакт `response.txt` лишається точною копією відповіді.
- **Body encoding: Raw** передає тіло прапорцем `-d`, а з файлового тіла curl
  вирізає переноси рядків — багаторядковий текст піде одним рядком. Скрипт це
  помічає й додає примітку; щоб надіслати тіло байт у байт, оберіть **Binary**
  або **JSON**.
- **Body encoding: URL-encoded** кодує весь вміст поля цілком. Раніше текст до
  першого `=` сприймався як ім'я поля й лишався незакодованим.
- **Verbose** (`-v`) показує трасування curl у звіті й тоді, коли запит успішний.

## Примітки у звіті

Якщо скрипт щось змінив у вашій команді або пропустив непідтримуване поле, він
не робить це мовчки: над результатом з'являється блок **Notes** зі списком того,
що саме сталося і чому.

## Результат

У вкладці **Results** — markdown-звіт: команда, код виходу, час, примітки,
діагностика curl, статусний рядок, таблиця заголовків, write-out і тіло
(обрізане до ~50 КБ; бінарне показує розмір). Артефакти:

- `command.sh` — точна команда (з замаскованими секретами), яку можна скопіювати в термінал.
- `headers.txt` — повні заголовки відповіді.
- `response.txt` — повне тіло (якщо увімкнено **Save body**).

## Код виходу й таймаут

Скрипт виходить з `0`, навіть коли curl завершився з помилкою. HTTP-статус і код
виходу curl завжди у звіті — це щоб запуск не світився червоним в History, коли
ви просто перевіряєте недоступний сервер. Винятки — `1`, якщо бінарника `curl`
немає в `PATH` або стався таймаут процесу; в обох випадках причина теж потрапляє
у звіт.

Часового ліміту з боку застосунку немає — дедлайн рахує сам скрипт за формулою
**Max time × (Retries + 1) + затримки між спробами + 10 с**. Так зроблено тому,
що `--max-time` в curl діє на кожну спробу окремо, тож із retries запит законно
триває довше, і фіксований ліміт застосунку вбивав би його на середині.

**Retry delay = 0** означає не «без паузи», а «типовий backoff curl»: 1 с із
подвоєнням на кожній спробі (до 10 хв). Скрипт закладає в дедлайн саме цей
backoff — інакше він убивав би curl посеред серії спроб.
