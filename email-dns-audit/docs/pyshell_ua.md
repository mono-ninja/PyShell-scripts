# Аудит поштового DNS

Перевіряє всі DNS-записи, що визначають, чи довіряють листу від домену чи
блокують його: **MX**, **SPF**, **DMARC**, **DKIM** (за селектором), і — за
окремими перемикачами — MTA-STS / TLS-RPT / BIMI. Результат — статус
pass/warn/fail по кожній опорі плюс одне речення готовності простою мовою;
саме це речення і є результатом, а таблиця по записах — підтвердження.

Пасивний за задумом: **лише DNS-запити** — поштова інфраструктура домену
ніколи не контактується. Єдиний виняток — опційна перевірка MTA-STS, яка
додатково завантажує `https://mta-sts.<domain>/.well-known/mta-sts.txt` і
помічена відповідно.

---

## Перед запуском

1. Натисніть **Prepare Env** — встановить `dnspython`.
2. **Домен** — без схеми (`example.com`).

---

## Поля

### Ціль

- **Домен** — домен, від імені якого надсилається пошта.
- **DKIM-селектори для перевірки** — DKIM-селектори **не можна відкрити
  через DNS**: скрипт пробує `<selector>._domainkey.<domain>` для кожного
  імені зі списку. Замовчування покриває поширені провайдерів (Google
  `google`, Microsoft 365 `selector1`/`selector2`, Mailchimp `k1`, Amazon
  SES `amazonses`, …). Порожній результат DKIM може означати лише те, що
  потрібного селектора немає у списку — файндинг каже це прямо, а не
  читається як «DKIM немає».
- **Кастомний резолвер** — напр. `1.1.1.1`; порожньо = системний резолвер.

### Додатково (вимкнені за замовчуванням)

- **MTA-STS** — `_mta-sts` TXT, плюс завантаження URL політики (єдиний
  не-DNS крок скрипта, тому він опційний). Перевіряє `mode:` політики
  (enforce / testing).
- **TLS-RPT** — `_smtp._tls` TXT, звіти про збої TLS-доставки.
- **BIMI** — `default._bimi` TXT (на практиці один поширений селектор).

---

## Що перевіряється

- **MX** — записи існують; кожен MX-хост реально резолвиться (MX на мертвий
  hostname тихо з'їдає пошту).
- **SPF** — рівно один запис `v=spf1` (більше одного — жорсткий fail:
  receivери вважають всю пошту SPF-permerror — поширена й непомітна
  помилка); ліміт 10 DNS-запитів з RFC 7208, порахований **рекурсивно по
  `include:`-цілях**; кінцевий кваліфікатор (`-all` pass / `~all` warn /
  `?all` або нічого → fail).
- **DMARC** — запис існує на `_dmarc.<domain>`; `v=DMARC1` першим;
  сила `p=` (none → warn, quarantine/reject → pass); `sp=` слабший за
  `p=`; `pct=` часткове застосування; звіти `rua=`; режими alignment.
- **DKIM** — по кожному селектору: `v=DKIM1`, тип ключа, `p=` непорожній
  (**порожній `p=` — відкликаний ключ** за RFC 8463 — повідомляється окремо
  від «запису немає»). Довжина ключа з public-key blob включена.

## Результат

- **Вкладка Results** — markdown-звіт: речення готовності, таблиця статусів
  по опорах, кожен файндинг із конкретним виправленням.
- **Артефакти** — `dns_records_raw.json` (усі фактично отримані записи,
  дослівно), `findings.json` (машиночитний, для CI), `report.md`.

## Код виходу

- `0` — домен резолвиться, перевірки відпрацювали, скільки б опор не
  провалилося. Домен, що повністю підробляється, — це успішний аудит із
  поганим результатом.
- `1` — домен не резолвиться (NXDOMAIN).
- `2` — середовище не готове (немає dnspython).
