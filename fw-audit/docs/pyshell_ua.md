# Аудит firewall

**Що правила firewall справді дозволяють** — компаньйон Port Check
по парі «правила проти реальності». Збережені дампи **ufw**,
**iptables**, **pf** і **firewalld** розглядаються пасивно (формат
впізнається автоматично, нічого не запускається від root, нічого не
змінюється): типові політики входу, кожен allow-правило вхідного
трафіку з його джерелом, ризикові порти, відкриті **наввмання**,
згруповані як у Port Check, allow-all правила, правила з прив'язкою
до джерела (похвалені, а не лише помічені), парність IPv6 і
затінення в iptables (deny, який ніколи не спрацює, бо вище стоїть
allow).

---

## Перед запуском

1. Експортуйте дамп на хості:
   `sudo ufw status verbose > ufw.txt` ·
   `sudo iptables-save > iptables.save` ·
   `sudo pfctl -sr > pf.txt` (або копія `pf.conf`) ·
   `sudo firewall-cmd --list-all > firewalld.txt`
2. Оберіть **Source** — один дамп, кілька або теку (кожен файл
   «нюхається»; файли без firewall-формату пропускаються з
   приміткою).
3. **Prepare Env** не потрібен — лише стандартна бібліотека.
   Натисніть **Run** (⌘↩).

## Поля

### Input

- **Source** — один / кілька / тека; `--recursive` у режимі теки
  заходить у підтеки.
- Формат кожного файла впізнається за вмістом — ufw (`Status:
  active`), iptables-save (`*filter` / `:INPUT`), pf
  (`pass`/`block`/анкор-синтаксис), firewalld (`зона (active)` +
  services/ports).
- Штатний macOS `pf.conf` (лише анкери, жодного pass/block)
  впізнається і чесно пояснюється: справжні правила живуть у
  анкор-файлах, на які він посилається.

## Результат

- **Вкладка Results** — таблиця (файл · формат · default-in ·
  правил · ризикових відкрито · вердикт) і звіт по кожному дампу:
  - **Allow-правила входу** — кожне з `→ Anywhere` або прив'язаним
    джерелом, і сирим рядком.
  - **Прапорці** — ризикові порти, відкриті світові
    (MySQL/Redis/тощо за групами ризику), allow-all і pass-all
    правила, затінені deny в iptables, відсутній `block all` у pf,
    неактивний ufw.
  - **Примітки** — кількість правил, парність IPv6 (v4-правила без
    v6-двійника), правила з прив'язкою до джерела (добра практика),
    виключення loopback, LIMIT-правила, назви зон firewalld.
  - **Як виглядає правильно** — deny за замовчуванням; менеджмент-
    порти з прив'язкою; бази даних — ніколи світові; попередження
    про Docker, що мовчки обходить ufw.
- **Артефакти** — `report.md`, `findings.json`.

### Вердикти

🔴 **default-open** (політика allow / allow-all правило / неактивний)
· 🟠 **risky ports open** · 🟢 **sane** · 🟡 **see notes** (pf без
`block all`, цілі зон firewalld, правила лише з анкорами). Жодних
догадок поза дампом: невпізнаний файл повідомляється як невпізнаний.

## Коди виходу

| Код | Значення |
|---|---|
| 0 | відпрацювало; знахідки у звіті |
| 1 | жоден файл не відповідає firewall-формату |
| 2 | помилкові аргументи: немає файла, порожня тека |

## Пов'язане

- **Port Check** — сторона дроту: що відповідає зараз. Проганяйте
  обидва по одному хосту; звіти створені читатися разом.
- **SSH Log Check** — що поглинав відкритий SSH-порт.
- **Secret Scan** — інша половина «що я лишилося відкритим»: ключі в
  репозиторії.
