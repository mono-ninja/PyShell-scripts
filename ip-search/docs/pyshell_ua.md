# IP Search

Визначає IP-адресу вказаного сайту **всіма доступними способами** і звіряє
результати між ними. Скрипт нічого не відправляє на ціль, крім звичайних
DNS-запитів і одного TCP/HTTP з'єднання, — це пасивна розвідка.

Усі методи резолву, хостинг-локапи по кожному IP та методи аналізу
виконуються **паралельно**, тож повний запуск триває приблизно стільки, скільки
найповільніший один метод (зазвичай traceroute), а не сума всіх.

## Перед запуском

- **URL сайта** — повна адреса (`https://example.com`) або просто домен
  (`example.com`). Схему можна опустити.
- **Timeout** — час очікування на одну операцію у секундах.
- **IPv6 (AAAA)** — чи додавати до результату IPv6-адреси.
- **Методи резолву** — які способи використовувати. Усі ввімкнені за замовчуванням:
  - `system` — системний резолвер через `socket.getaddrinfo` / `gethostbyname(_ex)`;
  - `dnspython` — бібліотечний резолвер плюс прямі UDP-запити до `8.8.8.8` і `1.1.1.1`;
  - `doh` — DNS-over-HTTPS (Google, Cloudflare, DNS.SB);
  - `dot` — DNS-over-TLS (Google, Cloudflare);
  - `connect` — пряме TCP/HTTP(S) з'єднання з читанням IP вузла, до якого реально підключились (`socket` + `http.client`);
  - `tools` — системні утиліти `dig`, `host`, `nslookup` (якщо встановлені);
  - `hosting` — визначення хостинг-провайдера по знайдених IP: RDAP-запит
    (організація, мережа, ASN, країна, CIDR), reverse DNS (PTR) та опціонально
    SSH-банер. RDAP-дані кешуються по мережі (CIDR), тому IP з одного блоку
    (типово для CDN) не запитуються повторно;
  - `dnsrecs` — додаткові DNS-записи домену: NS, MX, TXT, SOA, CAA (розкривають
    DNS-провайдера, поштовий хостинг, SPF/DKIM, політику сертифікації).
    Запити йдуть до **реєстрового домену** (apex), а не до `www.`-піддомену;
  - `whois` — WHOIS домену через RDAP: реєстратор, дати створення/оновлення/
    закінчення, nameservers, статус, DNSSEC. Запит йде до реєстрового домену;
  - `cdn` — детекція CDN/WAF: аналіз HTTP-заголовків (Server, CF-Ray, X-Fastly,
    X-Amz-Cf-Id тощо) та TLS-сертифіката (емітент, SANs);
  - `traceroute` — мережевий шлях до хоста через системну утиліту `traceroute`
    (показує транзитних провайдерів і хопи). При таймауті частковий результат
    зберігається.

- **SSH-банер** — коли увімкнено (разом з методом `hosting`), скрипт підключається
  до порту 22 кожного унікального IP і читає рядок привітання SSH
  (напр. `SSH-2.0-OpenSSH_8.9p1 Ubuntu-3ubuntu0.10`). Автентифікація не
  виконується — лише пасивне читання банера. Якщо RDAP-організація належить
  відомому CDN (Cloudflare, Fastly, AWS CloudFront тощо), банер пропускається,
  бо CDN-edge IP ніколи не відповідає по SSH — це зазначається у звіті.
- **Тека для артефактів** — куди записувати вихідні файли. За замовчуванням це
  тека PyShell (`$PYSHELL_OUTPUT_DIR`) або поточна директорія у CLI-режимі.
  Артефакти, які цей запуск не створює (напр. `traceroute.csv` без методу
  `traceroute`), видаляються, щоб не залишатися від попереднього запуску.

## Результат

- **Таблиця** всіх отриманих записів: метод, джерело, адреса (IP або CNAME),
  тип (A/AAAA/CNAME), TTL, статус, час, хостинг. Стовпець «hosting» завжди
  присутній (порожній, якщо метод `hosting` не запускався).
- **Markdown-підсумок** зі:
  - списком унікальних IP та кількістю **незалежних джерел**, що їх підтвердили
    (локальний резолвер / Google / Cloudflare / DNS.SB / observed peer) — а не
    просто кількістю методів, бо кілька методів можуть використовувати той самий
    резолвер;
  - розділом **розбіжностей** (Divergence): IP, які бачить лише локальний
    резолвер, але жоден публічний — ознака split-horizon DNS або перехоплення;
  - деталями хостингу (провайдер, ASN, країна, PTR, SSH-банер), DNS-записів,
    WHOIS домену, CDN/WAF-детекції та traceroute.
- Артефакти: `results.csv` (завжди 10 стовпців, включно з `hosting`), `results.json`
  (повні дані), `dns_records.csv` (лише з методом `dnsrecs`), `traceroute.csv`
  (лише з методом `traceroute`).

Методи, що залежать від відсутніх інструментів (напр. `dig` без встановленого
`dig` або DoT без `dnspython`), позначаються статусом `SKIPPED` — це не помилка.
Різні методи можуть повертати ті самі IP — це нормальна взаємна перевірка
(consensus). Розбіжності між методами вказують на CDN, балансування навантаження
або спотворення локальним резолвером.
