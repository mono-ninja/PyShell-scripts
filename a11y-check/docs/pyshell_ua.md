# Перевірка доступності

Статичний прохід доступності: контраст тексту по WCAG, обчислений з
CSS, який можна прочитати без запуску сторінки (колірний рушій Color
Palette + формула відносної яскравості WCAG, великий текст — поріг
3:1), форми без підписів, пропуски рівнів заголовків, `lang` на
`<html>`, ARIA-ролі без обов'язкового стану, `aria-hidden` на
фокусованих елементах, презентаційні ролі, які ARIA ігнорує,
позитивний `tabindex`, порожні посилання і
«click here», таблиці даних без `<th>`, iframe без title,
автовідтворення медіа, viewport, що блокує зум,
`<meta http-equiv="refresh">`, дублікати `id`, landmarks і skip-link.

Один запит — принцип Page SEO Audit. Те, чого статичний аналіз
побачити не може, звітується як **не перевірено**, ніколи як
«пройдено».

---

## Перед запуском

1. Введіть **URL** сторінки для перевірки.
2. **Prepare Env** — встановлює `requests` і `lxml`.
3. Натисніть **Run** (⌘↩).

## Поля

### Target

- **URL** — сторінка для перевірки; редіректи відслідковуються, у
  звіті — фінальний URL. Сторінку, що відповіла 404 або 500, скрипт
  теж аудитує (на сторінки помилок люди теж потрапляють) — статус
  зазначено у звіті.
- **Per-request timeout (s)** — завантаження сторінки і кожного
  стайлшиту.
- **Stylesheets for contrast** — скільки зв'язаних стайлшитів
  довантажити для контраст-проходу (0–10, типовo 3). Беруть участь
  лише правила з *одним простим* селектором (тег / `.клас` /
  `#id`) — це і є статична межа. Print-only і alternate стайлшити
  пропускаються, щоб бюджет ішов на те, що справді рендериться;
  `<base href>` і відносні шляхи розв'язуються так само, як у
  браузері.

## Результат

- **Вкладка Results** — таблиця (серйозність · перевірка · знахідка ·
  де) і звіт, згрупований за перевірками:
  - **contrast** — відношення, пара кольорів, недосягнутий поріг, по
    елементах (`тег#id.клас — «фрагмент тексту»`); плюс примітка,
    скільки пар статичний CSS зміг однозначно визначити, або чесне
    «не перевірено», якщо жодної.
  - **forms** — кожен контроль без підпису; тільки-placeholder,
    тільки-title і `for=`/`aria-labelledby`, що вказує на неіснуючий
    `id`, — кожне окремим попередженням.
  - **headings / lang / aria / focus / links / tables / media /
    meta / ids / landmarks** — кожна знахідка зі своїм виправленням.
  - **images** — кількість без alt з вказівкою на **Page SEO
    Audit** (alt — його колонка; цей скрипт не дублює).
- **Артефакти** — `report.md`, `findings.json` (кожна знахідка несе
  `count` і до трьох `examples`).

Однакові знахідки згортаються в один рядок із лічильником і кількома
прикладами: одна помилка в CSS — це одна знахідка, скільки б
елементів її не успадкувало. У таблиці — перші 60 рядків і
позначка, скільки ще є в `report.md`.

### Вердикти

🔴 помилки · 🟠 лише попередження · 🟢 чисто. Помилки —
WCAG-форматовані «мусить» (контраст нижче порога, взагалі без
підпису, aria-hidden на фокусованому, нема `lang`, таймер refresh);
попередження — «варто» (placeholder, підпис лише через title,
пропуск заголовка, позитивний tabindex, генеричний текст посилання,
заблокований зум, дублікати id, iframe без title); інформація —
контекст (landmarks, skip-link, кілька h1, іноземні вставки).

### Чесна межа

Без виконання JS і без computed styles. Контраст перевіряється всюди,
де каскад можна простежити статично: інлайнові стилі, прості
селектори, специфічність і успадкування вгору по ланцюжку предків —
успадкування є детермінованим механізмом CSS, а не здогадкою. Поза
межами і звітується як «не перевірено», а не «пройдено»: складені
селектори й селектори-нащадки, стилі з JS, кастомні властивості
(`var()`), `color-mix()` і текст поверх фонового зображення чи
градієнта. Коли фон не задекларовано ніде вгору по ланцюжку,
береться припущення білого канвасу браузера — і знахідка про це
прямо каже. Решту закриває ручна перевірка контрасту в DevTools.

## Коди виходу

| Код | Значення |
|---|---|
| 0 | відпрацювало; знахідки — результат (404-сторінку теж аудитуємо) |
| 1 | недосяжно, порожнє тіло або відповідь не є HTML |
| 2 | помилкові аргументи: URL без http(s) |

## Пов'язане

- **Contrast Matrix** — та сама математика WCAG по цілій палітрі ще
  до того, як сторінка існує, плюс APCA (Lc) як друга думка і
  найближчий відтінок, що проходить, для кожної пари з цього звіту.
- **Page SEO Audit** — той самий one-fetch прохід по сигналах
  пошукової видимості (title, meta, заголовки, alt).
- **Color Palette** — колірний рушій, з якого виросла ця
  контраст-математика; використовуйте його, коли обираєте
  доступну палітру.
- **Site Crawler → SEO Checks** — прохід по всьому сайту; цей
  скрипт — глибокий по одній сторінці.
