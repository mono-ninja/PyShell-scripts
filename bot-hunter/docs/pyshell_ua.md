# Bot Hunter

Аналізатор логів веб-сервера для SEO: виявляє боти, оптимізує crawl budget,
генерує правила блокування скрейперів. Нічого не відправляє в мережу — тільки
читає локальні лог-файли та пише звіти.

## Поля

- **Logs directory** — тека з логами Apache/Nginx (формати combined та
  vhost_combined). Підтримуються `.log`, `.txt`, `.gz`, `.bz2`, сканування
  рекурсивне. Покладіть сюди файли `access.log*` з сервера.
- **Domain** — домен сайту для звіту (наприклад `example.com`). Потрібен лише
  для заголовка звіту та імен файлів; самі логи не фільтруються за доменом.
- **Max lines per file** — обмеження кількості рядків на файл. `0` = без обмежень.
  Корисно для швидкого тестування на великих логах.
- **Skip blocking rules** — не генерувати `nginx.conf` та `.htaccess`. За
  замовчуванням правила створюються завжди.
- **Report format** — `HTML` для перегляду та відправки клієнтам, `JSON` для
  програмної обробки, `HTML + JSON` для архіву.
- **Verbose** — друкувати список знайдених файлів та детальний прогрес.

## Що в результаті

- **Progress bar** — показує парсинг логів (0-80%), виявлення ботів (80-85%),
  генерацію звітів (85-100%).
- **Tables** — активність ботів (топ-20), disguised bots (IP з browser UA але
  bot-поведінкою), правила блокування.
- **Charts** — розподіл запитів за категоріями ботів (search, scraper, AI...),
  розподіл HTTP статус-кодів.
- **Markdown report** — повний звіт у вкладці Results: підсумок, таблиця ботів,
  виявлені загрози, правила блокування, рекомендації robots.txt.
- **Artifacts** — файли у вкладці артефактів:
  - `YYYY-MM-DD_domain.html` — повний HTML-звіт
  - `YYYY-MM-DD_domain.json` — сирі дані (якщо обрано)
  - `YYYY-MM-DD_domain.nginx.conf` — правила блокування для nginx
  - `YYYY-MM-DD_domain.htaccess` — правила блокування для Apache
  - `YYYY-MM-DD_domain.robots.txt` — рекомендований robots.txt

## Що виявляє

1. **Відомі боти** — Googlebot, Bingbot, Yandex, GPTBot, Claude-Web, AhrefsBot
   тощо (46 сигнатур). Кожен маркується як легітимний чи ні.
2. **Disguised bots** — IP-адреси з browser User-Agent, але систематичним
   скануванням (`/wp-json/`, `/plugins/`, висока різноманітність URL). Ці запити
   рахуються як human, але насправді — боти.
3. **Підозрілі підмережі** — /24 (IPv4) або /64 (IPv6) діапазони з 3+ IP-адрес
   або високим трафіком, що вказує на ботнет або розподілений скрейпер.
   Легітимні боти (Google, Bing) виключаються.
4. **Crawl budget waste** — топ 404 URL, топ 301 redirects, які витрачають
   бюджет індексатора.
5. **Google rate limiting** — відсоток 429 відповідей для Google-ботів, пікові
   години, рекомендації.
6. **Діагностика форматів і пропусків** — звіт показує, які формати логів
   розпізнано (`combined` / `vhost_combined`), та класифікує рядки, що не
   відповідають жодному (`php-fpm`, `vhost-combined`, `no-match`), тож parse
   rate є meaningful сигналом здоров'я парсера.

## Код виходу

`0` при успіху: знайдені боти та загрози — це результат аналізу, а не помилка
скрипта. Дані у таблицях та звіті. `1` означає, що запуск узагалі не
відбувся — не вказано домен, відсутня тека логів або не знайдено вказаний
користувачем `--config`.

## Локальний запуск

Поза PyShell скрипт працює як звичайний CLI:

```bash
python main.py --domain example.com
python main.py --domain example.com --format json --verbose
python main.py --logs-dir /var/log/nginx --domain example.com
```

Звіти пишуться у `reports/`. При використанні `--output` всі артефакти
(звіт, robots.txt, правила блокування) зберігаються поруч із вказаним файлом;
вміст звіту визначає `--format` — варіант `both` пише HTML- та JSON-звіти поруч,
а розширення, що суперечить `--format`, викликає попередження замість
мовчазного застосування. Помилки читання логів виводяться у stderr.
