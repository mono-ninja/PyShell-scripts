# Перевірка експозиції WordPress

Перевіряє, які **двері WordPress сайт лишає відчиненими** — відомі
ендпоінти, які просить перший рекогнавальний залп будь-якого сканера.
По одному **пасивному GET** на ендпоінт, редіректи відстежуються, без
POST-запитів і спроб входу: не надсилається нічого, чого не надсилають
тисячі звичайних відвідувачів. Кожен ендпоінт повертається з вердиктом —
exposed / protected / not found — доказом, який його заробив, і
**способом закрити**, якщо він відкритий.

Компаньйон [Log Attack Checker](../../log-attack-checker): той скрипт
показує, як виглядають атаки у ваших логах, цей каже, **які відчинені
двері дозволяють їм вдаватись**.

---

## Перед запуском

1. **Site URL** — базова адреса WordPress-сайту, яким ви володієте або
   за який відповідаєте (`https://example.com`). Опитується лише цей
   хост; глибокий шлях обрізається до кореня — ендпоінти живуть там.
2. Натисніть **Prepare Env** — встановить `requests`.
3. Натисніть **Run** (⌘↩). Сім ендпоінтів, секунди.

## Поля

### Target

- **Site URL** — `https://…`. Спершу один раз береться головна: вона
  доводить, що ціль відповідає (недосяжний сайт — exit 1, перевіряти
  було нічого), і збирає маркери WordPress.
- **Per-request timeout (s)** — один GET на ендпоінт, стільки часу на
  кожен.

### CI

- **Fail the run on** — `nothing` (замовчування: експозиції — це
  результати, а не помилки) або `any` (exit 3, коли хоч один ендпоінт
  відкритий — CI-гейт).

---

## Що перевіряється

| Ендпоінт | Чому це важливо |
|---|---|
| `/wp-json/wp/v2/users` | Перелік користувачів — логіни, які пробує брутфорс. Варіант `?rest_route=` пробується вдруге, коли pretty-маршрут закритий: фільтр може блокувати одне і не блокувати інше. |
| `/xmlrpc.php` | Живий XML-RPC (405 «accepts POST only») — підсилювач pingback-DoS і перебору креденшалів. |
| `/readme.html` | Йде з кожним інсталом; називає точну версію. |
| `/wp-content/debug.log` | Debug-виведення, лишене в webroot — віддається як звичайний файл. |
| `/wp-content/uploads/` | Список медіа-каталогу, який можна гортати (сторінка «Index of»). |
| `/wp-login.php` | Інформаційне: досяжність нормальна для WP; ризик — брутфорс, який іде слідом, і його міряє Log Attack Checker. |
| `<meta generator>` головної | Інший витік версії — читається з уже взятої головної, без додаткового запиту. |

Soft-404 обробляються чесно: 200, що віддає HTML-сторінку там, де мав
бути лог або JSON-список, **не** рахується як exposed.

## Результат

- **Results tab** — таблиця ендпоінтів (статус · перевірка · що побачено),
  потім звіт: кожна перевірка з доказом, а для кожної експозиції — спосіб
  закрити, впорядковано «спершу виправити» (high перед medium).
- **Артефакти** — `findings.json` (кожна перевірка, машиночитабельно),
  `report.md`.

Коли на головній **взагалі нема маркерів WordPress** (нема шляхів
wp-content, посилання wp-json, генератора), звіт так і каже — сайт може
не бути WordPress; вердикти по ендпоінтам самі по собі лишаються в силі.

## Коди виходу

- `0` — перевірку виконано. Експозиції — результати, а не помилки.
- `1` — ціль не відповіла, або сама головна відповіла HTTP-помилкою:
  зламаний сайт не можна перевірити на експозицію.
- `2` — неправильні аргументи (нема схеми/хоста).
- `3` — спрацював опційний CI-гейт (`--fail-on any`).
