# Мінімізація ассетів

Мінімізує CSS і JS **вбудованим рушієм на чистому Python** — без npm і
без залежностей — а коли в системі встановлені **системні бінарці**
(terser для JS, clean-css-cli для CSS), віддає роботу їм, бо вони
стискають сильніше. Python в обох випадках — оркестрація: пошук
файлів, покрокові запуски, чесний звіт.

---

## Перед запуском

Встановлювати нічого не треба: вбудований рушій працює завжди, а
**Prepare Env** не має чого робити (Python-залежностей нема).

Жоден коментар не переживає прогін, хай яким рушієм: системні бінарки
викликаються з `--comments false` / `specialComments:0`, щоб збігатися
з вбудованим.

Опційно — заради сильнішого стиснення JS: terser скорочує імена змінних
і викидає мертвий код, чого вбудований рушій свідомо не робить:

```bash
npm install -g terser clean-css-cli
```

1. Оберіть **Source** — один файл, кілька або папку (з фільтром
   CSS/JS і перемикачем **Recursive**).
2. Оберіть **Output folder** і натисніть **Run** (⌘↩).

## Поля

### Input

- **Source** — single / multiple / folder.
- **Only** (режим папки) — CSS, JS чи обидва.
- **Recursive** (режим папки) — обходити підпапки; вихід зберігає
  структуру.

### Options

- **Engine**
  - *Automatic* (типово) — системна бінарка для кожного типу, якщо
    вона встановлена, інакше вбудований мінімізатор. Відсутня бінарка
    тут не помилка, а лише слабший результат. Пошук іде не лише по
    `PATH`, а й у типових теках npm (`/opt/homebrew/bin`,
    `/usr/local/bin`, `~/.npm-global/bin`, …): запуск із застосунку
    успадковує урізаний `PATH` і інакше просто не побачив би
    встановлений terser. Якщо бінарка знайшлася, але впала на файлі —
    цей файл дообробить вбудований рушій, а в примітці рядка буде
    скарга самої бінарки.
  - *Built-in* — ніколи не викликає зовнішніх програм. Передбачувано,
    без залежностей, і це єдиний варіант на машині без Node.
  - *System binaries* — вимагає terser / clean-css-cli і зупиняється з
    точним рядком `npm install -g …`, якщо чогось нема. Беріть, коли
    важливе саме максимальне стиснення й мовчазне падіння на запасний
    рушій було б гіршим за помилку.

### Output

- **Output folder** — куди пишуться `.min.css` / `.min.js`. Оригінали
  ніколи не змінюються.
- **Overwrite existing** — коли вимкнено, `.min`-файли, що вже є у
  виході, пропускаються (зі звітом, не мовчки).

## Що вміє вбудований рушій

- **CSS** — прибирає **всі** коментарі, і ліцензійні банери `/*!`, і
  секційні `/* ===== */`, стискає пробіли, знімає останню `;` у блоці,
  скорочує `#aabbcc` до `#abc` і `0.50em` до `.5em`. І не лізе туди, де пробіл щось значить: усередині
  `calc()` / `clamp()` / `min()` / `max()` та перед `:` — бо `a :hover`
  і `a:hover` це різні селектори. Зазвичай 15–25% від рукописного CSS.
- **JS** — справжній токенізатор: регулярні вирази відрізняються від
  ділення, шаблонні літерали (з вкладеними `${…}`) копіюються цілком.
  Усі коментарі (разом із банерами `/*!`) і всі зайві пробіли зникають,
  а перенос рядка, який був у джерелі, **зберігається** скрізь, де від
  нього може залежати
  автоматична вставка крапки з комою — тож `return` ніколи не
  приклеїться до наступного рядка. Імена змінних не скорочуються і
  мертвий код не викидається: для цього потрібен повний парсер, а це
  робота terser. Зазвичай 20–30% проти 50–70% у terser.

## Результат

- **Results tab** — таблиця по файлах (файл · тип · рушій · статус ·
  % економії · примітка) і підсумок (байт зекономлено, лічильники за
  статусами).
- **Артефакти** — `minification_report.csv`.

### Статуси

- **minified** — `.min`-файл записано; розміри та % економії показані.
- **already minimal** — вихід мінімізатора виявився більшим або рівним
  джерелу: `.min`-файл не пишеться. Трапляється для ручних або
  вже мінімізованих файлів; рядок — це результат, а не помилка.
- **skipped** — вхід `*.min.*` (мінімізувати мінімізоване — марна
  праця) або наявний вихід без Overwrite.
- **error** — цей файл не вдався; примітка несе перший рядок stderr
  бінарки або скаргу вбудованого рушія (незакритий літерал, файл не в
  UTF-8). Один поганий файл ніколи не зупиняє партію.

## Коди виходу

- `0` — партію оброблено.
- `1` — **Engine: System binaries** з відсутньою бінаркою (друкується
  точний рядок `npm install -g …`), непридатна вихідна папка, або
  кожен файл зазнав помилки.
- `2` — неправильні аргументи.
