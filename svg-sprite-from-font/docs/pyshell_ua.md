# SVG Sprite — From Font

Перетворює існуючий іконочний шрифт (FontAwesome 4, IcoMoon, власні набори
IcoMoon) на сучасний SVG-спрайт у форматі `<symbol>`. Практичний сценарій —
успадкований WordPress-шаблон, де шрифт вбудований, а оригінальні SVG давно
втрачені: лишилися лише файли шрифту та CSS.

## ⚠️ Ліцензія — прочитайте перед запуском

Вилучення контурів зі шрифту — це питання **поширення (redistribution)**, а не
техніки. FontAwesome Pro, Linearicons і більшість платних наборів забороняють
це прямо. Інструмент читає таблицю `name` шрифту (авторське право та ліцензію),
показує її як статус і **зупиняється без запису файлів**, якщо ліцензія
обмежувальна, а прапорець **«I have redistribution rights»** (`--i-have-the-rights`)
не встановлено. Текст ліцензії друкується завжди — щоб оператор, у якого є права,
бачив, що саме він скасовує.

Для перmissive-ліцензій (OFL, Apache, MIT, BSD, Public Domain) запис іде й без
прапорця. Якщо ліцензію не вдалося класифікувати — ідемо далі, але на ваш риск:
SVG-шрифти не мають таблиці `name` тож завжди потрапляють у цю категорію.

## Перед запуском

- **Font file** — `.ttf`, `.otf`, `.woff`, `.woff2` або SVG-шрифт (`.svg` з
  `<font>`). `.eot` не підтримується (дайте TTF).
- **Accompanying CSS** — найважливіше необов'язкове поле. Саме тут живуть
  людиночитні імена: `.icon-user:before { content: "\e900" }`. Без CSS імена
  беруться з `post`-таблиці (інколи `glyph42`) або лігатур, а без них —
  fallback `icon-uniE900`.
- **Existing names.json** — повторний запуск. Вивід попереднього запуску
  (`names.json`) можна відредагувати вручну: при наявності файла він
  перечитується і має пріоритет над усім іншим.
- **Flatten transform** (увімкнено) — вбудовує y-flip у дані шляху через
  `svgpathtools` замість обгортки `<g>`. Менший вихід і жодних конфліктів з
  CSS, накладеним на `<use>`.
- **Fit** — `advance` (вірно до side-bearing шрифту, за замовчуванням) чи
  `bbox` (візуально нормалізовано: viewBox обрізається до реального bbox
  іконки + Padding). `bbox` корисний, коли іконки «плавають» у широких
  side-bearing і виглядають зміщеними поруч із вручну збудованим спрайтом.
- **Restrict to icons found in the theme** + **Theme folder to scan** —
  обходить `.php`, `.html`, `.js`, `.css` у шаблоні, шукає legacy-класи й
  залишає лише використані іконки. Працює для шрифтів на основі класів
  (FontAwesome 4, IcoMoon). Звітуються обидві цифри: знайдено у шрифті /
  реально використано.

## Результат

У вкладці **Results** — таблиця: codepoint, residual symbol id, джерело імені
(CSS / `post` / GSUB / fallback / names.json), попередження. Артефакти у вкладці
файлів:

- `sprite.svg` — спрайт `<symbol>`.
- `catalog.html` — сітка з двома колонками: іконка зі спрайту через `<use>`
  поруч із тією ж іконкою з оригінального шрифту (як `@font-face` base64). Це
  єдиний чесний спосіб побачити дефекти геометрії (B5) одразу. Для SVG-шрифтів
  оригінал не рендериться (браузери прибрали SVG-шрифти) — замість нього нотатка.
- `names.json` — кодпоінт → ім'я → джерело. Редагуйте й перезапускайте.
- `sprite.php` — WordPress-include: хук `wp_body_open` (з фолбеком `wp_footer`)
  друкує спрайт один раз, помічник `mn_icon( $name, $class, $label )` рендерить
  `<use>` з `aria-hidden` або `role="img"` + `<title>`.
- `migration.css` — **головний артефакт міграції**. Кожен legacy-клас
  (`.fa-user`) maps на `mask-image: url("sprite.svg#icon-user")`, а `::before`
  контент зануляється. Розмітку `<i class="fa fa-user"></i>` чіпати не треба —
  вона працює і після видалення файла шрифту. Завантажуйте **після** CSS
  іконочного шрифту шаблону.

## Коди виходу

- `0` — успіх (наявність безіменних іконок не робить код ненульовим — це
  частковий успіх, дані в таблиці).
- `2` — вхід не розпізнено / витяг неможливий (підтримка `.eot`, COLR-шрифт,
  битий файл). Файли не пишуться.
- `3` — ліцензійний шлюз: обмежувальна ліцензія без `--i-have-the-rights`.
  Файли не пишуться.
