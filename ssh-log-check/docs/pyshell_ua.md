# Перевірка SSH-логів

Відповідає на питання, які тримає sshd-лог: хто б'є по серверу, які
логіни пробує і — головне — **чи хтось із них увійшов**. Третій брат
родини лог-аналізаторів: [Bot Hunter](../../bot-hunter) класифікує
ботів, [Log Attack Checker](../../log-attack-checker) читає веб-атаки,
цей читає SSH.

Лише читає логи. Єдиний вихідний трафік — опційний GeoIP-пошук IP
злочинців (безкоштовний batch-ендпоінт ip-api.com); `--skip-geoip`
робить ран повністю офлайн.

---

## Перед запуском

1. Скопіюйте логи з сервера в одну папку: `auth.log`, `auth.log.1`,
   `auth.log.2.gz`, `secure`, дамп `journalctl -u ssh`
   (текст/JSON) або експорт macOS `log show`. Формат визначається
   **по кожному файлу**; те, що не парситься, звітується як
   пропущене, ніколи не мовчки.
2. Натисніть **Prepare Env** — встановить `requests`.
3. Вкажіть **Logs directory** на папку, натисніть **Run** (⌘↩).

## Поля

### Source

- **Logs directory** — одна папка, без рекурсії. `.gz`-файли
  розпаковуються на льоту.
- **Whitelisted IPs** — ваші власні адреси (офісний NAT, VPN-шлюз):
  помилковий пароль звідти — не атака, і залишення їх порушило б
  кожен лічильник.

### Detection

- **Brute-force threshold** — невдалих спроб з одного IP достатньо,
  щоб його позначити. Замовчування 5 (вікно fail2ban рахує 3–5).
- **Top N in tables** — рядків у таблицях; `findings.json` тримає
  усе.

### GeoIP

- **Skip GeoIP lookup** — вимкнено за замовчуванням: IP атакуючих
  отримують країну та прапорці proxy/hosting через ip-api.com.
  Увімкнено = повністю офлайн.
- **GeoIP lookup limit** — скільки різних IP збагатити, спершу
  найактивніші (безкоштовний тір має ліміти).

## Що виявляється

| Патерн | Значення |
|---|---|
| `Failed password for … from IP` | невдала спроба пароля |
| `Invalid user … from IP` | логіна не існує — шум зондів, але він мапує словник атакуючого |
| `maximum authentication attempts exceeded` | sshd відмовив тому IP |
| `Disconnected/Connection closed … [preauth]` | preauth-шум зондів (рахується, не позначається) |
| `Accepted … for user from IP` | успішний вхід — метод (publickey/password) записано |
| **невдачі → успіх, той самий IP** | критичний ланцюжок: IP, що зазнавав невдач, а потім увійшов. Звіт ставить їх у червоне — рятуйте ці креденшели раніше за все |

## Результат

- **Results tab** — таблиця брутфорс-IP (IP · невдач · пробуваних
  логінів · увійшов? · остання активність · країна), потім звіт:
  червона секція «невдачі-потом-успіх», таблиця брутфорс-IP, словник
  пробуваних логінів, успішні входи і наступні кроки.
- **Артефакти** — `report.md`; `findings.json` (кожен позначений IP з
  логінами, входами, мітками часу, geo); `fail2ban_jail.conf` —
  готовий sshd-jail для `/etc/fail2ban/jail.local` із
  прокоментованими злочинцями та ufw-рядками блокування. **IP, що
  також увійшли, ніколи не пропонуються до сирого блоку** — заблокувати
  власні витікані креденшели означає замкнути себе; вони позначені
  «ALSO ACCEPTED A LOGIN».

### Чесне читання даних

- Евристика «невдачі-потом-успіх» списує кожен IP, що і зазнавав
  невдач, і успішно входив. IP з горсткою невдач і роками успішних
  входів ключем — імовірно, людина, що помиляється; лічильники
  показані, щоб ви судили самі; заголовок секції каже «можливо,
  перемогли», а не «перемогли».
- Мітки часу syslog не мають року — застосована евристика
  переходу року («майбутній» місяць означає торішній лог).
  IP із вайтлиста виключаються повністю, за дизайном: лічильники
  тоді описують усіх інших.

## Коди виходу

- `0` — аналіз виконано. Брутфорс і скомпрометовані акаунти —
  знахідки, а не помилки.
- `1` — жодних sshd-подій у жодному файлі (не та папка або
  непідтримуваний формат — лог називає пропущені файли).
- `2` — неправильні аргументи (шлях не папка).
