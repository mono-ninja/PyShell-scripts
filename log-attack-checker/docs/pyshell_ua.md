# Log Attack Checker

Аналізує Apache/Nginx access-логи на наявність атак, орієнтованих на
WordPress-сайти: SQL-ін'єкції, XSS, path traversal, LFI/RFI, брутфорс
`wp-login.php` / `xmlrpc.php`, сканування плагінів і тем, спроби веб-шелів у
`/wp-content/uploads/` тощо. Нічого не надсилає на цільовий сайт — лише читає
файли логів і будує звіти.

## Перед запуском

- **Logs directory** — тека з файлами `.log` (або ротейт-файлами `.log.1`,
  `.log.2`). Очікується Combined Log Format:
  `IP - - [дата] "METHOD PATH PROTO" STATUS SIZE "REFERER" "UA"`.
  Обробка паралелізується по ядрах CPU через байтові ділянки файлів.
- **Site domain** — домен сайту (наприклад `example.com`). Потрібен для команд
  cURL у HTML-звіті; за ним автоматично резолвиться IP через DNS. Домен і IP
  показуються в терміналі, у шапці `report.html` та в командах cURL всередині
  нього; у `report.md` та `report.json` вони не потрапляють.
- **Whitelisted IPs** — IP-адреси, які повністю виключаються з аналізу
  (власний трафік, моніторинг). Вводьте через кому або пробіл:
  `1.2.3.4,5.6.7.8`.
- **Detection thresholds** — пороги для всіх детекторів (брутфорс, 404-flood,
  cron-flood, rate limit, ланцюги атак). Зменште поріг, щоб ловити менші
  сплески; збільште, щоб знизити кількість хибних спрацьовувань на завантаженому
  сайті. Усі детектори працюють у ковзному вікні **Time window (minutes)**.
- **GeoIP** — країна та прапорці Proxy/VPN і Hosting/Datacenter для
  топ-атакуючих IP через `ip-api.com` (batch endpoint, безкоштовно, без
  ключа). Рекомендація щодо геоблокування зважає за обсягом запитів, а не за
  кількістю IP, і показується лише при ≥10 looked-up IP. Увімкніть
  **Skip GeoIP lookups**, щоб повністю уникнути мережі.

## Хід виконання

Прогрес і статус передаються структурованими подіями: парсинг логів →
детектори → агрегація → GeoIP → побудова звітів. У вкладці **Results**
наприкінці з'являються:

- підсумкова **таблиця** метрик;
- **графік** запитів проти атак по годинах (останні 48 годин, дата — у мітках);
- **markdown-вердикт** із критичними знахідками (зламані акаунти, успішні
  атаки, топ-атакуючі IP).

## Артефакти

Усі три звіти пишуться у теку `PYSHELL_OUTPUT_DIR`:

- **report.html** — самодостатній темний HTML: чутливі файли під атакою,
  план загартування з готовими блоками Nginx / Apache / cURL (з реальним
  доменом замість `https://SITE`), графік таймлайну, таблиці IP.
- **report.md** — повний markdown-звіт для вставки в AI-асистента.
- **report.json** — машинно-читний вивід для SIEM / Grafana.

## Класифікація та вердикт

Кожен запит із патерном атаки класифікується як **SUCCESS** (2xx/3xx),
**Vulnerable** (500 — ендпоінт існує й впав) або **Blocked**. Підсумковий
вердикт обирається за найвищою тяжкістю: зламані акаунти (брутфорс + успішний
логін) → веб-шел у uploads → успішні дії плагіна → витік даних → успішні атаки
→ вразливі ендпоінти → ланцюги атак → брутфорс.

## Мережа

Лише GeoIP ходить у зовнішню мережу (`ip-api.com`). DNS-резолв домену сайту
виконується локально через `socket.gethostbyname`. PyShell не ізолює процес —
скрипт має ті самі права, що й ви.

## Код виходу

- `0` — аналіз завершено. Знайдені атаки — це результат аналізу, а не збій
  скрипта; знахідки — у таблиці/графіку/markdown та у файлах звітів.
- `1` — фатальна помилка: теку логів не знайдено, або в ній немає файлів
  `.log` / `.log.N` (у повідомленні перелічено непідтримувані файли, які
  було проігноровано, наприклад стиснуті ротейт-логи).
- `2` — некоректний аргумент (наприклад, поріг детектора нижче мінімуму);
  argparse виводить прийнятне значення у stderr.
